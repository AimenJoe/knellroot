# 0252 — Android 화면 밀도(dp)·도감 그림 손으로 보기

- 날짜: 2026-11-19
- 상태: 정함(사장 2026-11-19 — "안드로이드에서 폰트 제대로 안 나옴 · 터치스크린 가운데에 버튼 모여 있음 · 도감의 아이템 및 생물들도 잘 안 보임. 드래그로 살펴볼 수 있어야 함")

## 0. 웹(PWA) 가로: 터치 버튼·HUD가 가운데로 몰림(고침 — 사장 "가로모드 버그는 PWA의 문제인 듯")
- 원인: 0248의 안전 영역 재기(`web/index.html` `measureSafe`)가 env(safe-area-inset-*)의 CSS px에 **devicePixelRatio를 한 번 더 곱했다**.
  게임의 단위(`screen_width()`)는 번들이 캔버스 화소를 dpi로 나눈 CSS px라, 폰(배율 2.6~3)에서는 노치·카메라 홈을 비키는 폭이 2~3배가
  되어 버튼 무리·멈춤 버튼·HUD가 안쪽으로 밀렸다(헤드리스 915×412 배율 2.625 + 가로 홈 32px를 흉내: 비킨 폭 84 → 고친 뒤 32).
- 고침: 곱하지 않는다(CSS px 그대로). 안전 영역이 0인 기기(데스크톱·홈 없는 폰)는 처음부터 영향이 없었다.

## 1. Android APK 터치 버튼(고침)
- 원인: miniquad의 Android 백엔드는 dpi 배율을 늘 1로 두어 게임의 화면 단위가 **물리 화소**다(웹·iOS는 dp). 터치 버튼 크기의 상한
  `TOUCH_U_MAX` 520(태블릿에서 버튼이 너무 커지지 않게)이 화소로 걸려, 2400×1080 폰에서는 짧은 변 1080 대신 520으로 짜여 버튼이
  오른쪽 아래에 작게 몰렸다(헤드리스 2400×1080 배율 1로 재현). 탭 범위(24)·꼬집기 걸음(60)·끌어 돌리는 시점도 화소로 셌다(손가락
  거리 대비 2~3배 예민).
- 고침: 패치한 miniquad가 `DisplayMetrics.density`를 넘긴다(`QuadNative.activityOnDensity` → `native::display_density`, PATCHED.md).
  게임은 `screen::dp()`(dp 하나가 몇 화면 단위 — Android = 밀도, 그 밖 1, 못 받았으면 짧은 변/400)로 상한·탭 범위·꼬집기를 dp로 재고,
  터치로 끈 시점 거리도 dp로 나눈다. 웹·iOS·데스크톱은 그대로(dp = 1).

## 2. Android 글꼴(확인 중 — 위 0의 안전 영역 탓에 HUD 글이 화살표·버튼과 겹쳤던 것일 수 있다)
- 에뮬레이터 연기 시험(android-smoke, 640×320)의 타이틀·깨어나는 글은 바르게 나온다. 메뉴·HUD 글은 화면 높이에 맞춘 UI 배율이라
  dpi와 상관없다. 증상(깨짐·흐림·작음·빈 칸)을 사장의 화면으로 확인한 뒤 고친다 — 그 전에 넘겨짚어 바꾸지 않는다.

## 3. 도감 그림 손으로 보기
- 그림 위를 가로로 끌면(마우스·손가락, 패드는 오른쪽 스틱) 돌고 — 장비 탭 인형(0235)과 같은 `tabs::turn_by_hand` —
  누르면(확인) 창 가득 크게, 크게 본 동안도 끌어 돌리고 누르기·뒤로면 돌아온다. 크게 보는 동안 탭은 넘기지 않는다.
  고른 줄이 바뀌면 처음(저절로 흔들기)으로. 평소 그림 칸도 키웠다(생물 52×72 → 60×84, 물건 64 → 76).
- 상태는 `app::codex::CodexView`(각·그린 자리·크게) — 앱에 한 칸. 글 둘(`verb_enlarge`·`verb_drag_turn`, 한·영).
