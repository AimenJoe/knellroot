# 0283 — 빌려 쓰던 방랑자 동작을 Meshy API로 받은 제 동작으로

- 날짜: 2026-11-27
- 상태: **만듦**(판정 전 — 체크리스트 132)
- 사장: 설문 "새 무기 동작을 Meshy로 받을까요? 지금은 대검·창·쌍단검·낫이 한손검 동작을 빌려 씁니다"에 — "지팡이는 이제 타격이 덜 화려해야될것
  같긴 한데... 마법이 주력이아야 하잖아?", 설문 전체에 "마일스톤이라고 표현하긴 했지만, 0.9.x 에서 다 진행되어야해". 오늘 "Meshy에서 새로 받을
  줄 알았다"고 확인. 늘 있는 규칙: "Meshy API는 필요하면 불러도 된다, 쓴 크레딧만 알린다"(2026-11-17). 이번 일의 상한 200 크레딧.

## 왜
0193·0198·0206의 동작 묶음은 사장이 Meshy 웹에서 받은 것이었고, 0247 뒤로는 새 몸(v3)에 그 49개를 옮겨 담아 썼다. 그래서 0274의 새 무기와 0280의
빈 노드 넷은 있는 동작을 나눠 빌렸다 — 낫의 1 · 2타는 한손검의 `attack` · `attack2` 그대로, 창의 찌르기 셋은 검 3타의 원본(Thrust_Slash),
대검의 2 · 4타는 검 2타 · 검 강타의 원본, 쌍단검 셋째는 검 1타의 원본, 빈 노드 넷은 꿰뚫기 · 파문 · 던지기 · 불길의 클립을 이름째 빌렸다.

## 한 것(길)
1. **리깅**(`tools/art/meshy_rigging.py` — 0283에 GLB 파일을 data URI로 올리는 길을 더함). 0247의 v3 리깅 작업은 만료되어 다시 리깅해야 했다.
   v3 몸 원본(`raccoon_v3.glb`)과 v3 리그(`raccoon_v3_rig.glb`)는 둘 다 "predicted skeleton is missing core joints"로 실패(실패는 환불 — 0 크레딧).
   v2 몸 원본(`raccoon_v2.glb`)은 됐다(mixamo + 손가락). 동작은 뼈 이름(`mixamorig:*`)으로 옮겨 담으므로 어느 몸에 리깅했는지는 상관없다(0247과 같은 길).
2. **동작 받기**(새 스크립트 `tools/art/meshy_animation.py`): 라이브러리 동작(`apply --actions`) 또는 Text to Motion(`motion` → `apply --motion`).
   라이브러리 805개를 미리보기 GIF로 먼저 골랐다(0 크레딧) — 무기를 쥔 동작이 적고(검·도끼·활 위주) 창·낫·쌍단검·대검의 동작이 없어 대부분 Text to Motion(prime)으로 받았다.
3. **옮겨 담기**(새 `tools/art/blender/meshy_moves.py` + `retarget.py`): 받은 GLB들을 v3 뼈대로 옮겨(0247의 `retarget`을 `meshy_rig.py`에서 떼어 냄 —
   두 스크립트가 같이 쓴다) 뼈대만의 원본 `tools/art/sources/meshy/raccoon_v3_moves.glb`(1.04 MB, 동작 9)에 모은다. 받은 GLB(각 12~14 MB)는 레포에 넣지 않는다.
4. **게임 클립**(`wanderer_skin.py`): `raccoon_v3_rig_anim.glb`에 더해 `MOVES`의 동작도 읽는다(두 뼈대의 쉬는 자세가 같은지 뼈마다 본다 — 다르면 멈춘다).
   표 `CLIPS`가 원본 구간 → 게임 이름, 길이 · 판정의 순간은 예전 그대로(스킬은 `Clip::seg`, 평타는 `HIT_WINDOWS`).
   다시 만든 `wanderer.glb`에서 **바꾸지 않은 클립은 한 바이트도 안 바뀌었다**(몸 메시 · 노드 같음, 동작 데이터 해시 비교). 같은 입력으로 두 번 만들면 파일이 같다.

  작업이 만들어졌으므로 유료 플랜이다. **플랜의 이름과 유료 결과물의 이용 조건은 API로 알 수 없었고 약관을 확인하지 못했다**(0193의 Pro 동작과 같은 처지 — 사장 확인).

## 바뀌지 않은 것(안전망)
- 로직은 그대로: 클립의 길이 · 판정의 순간은 표에서 온다. `golden_traces` · `scenario_traces` · `fx_traces` · 사건 표 스냅숏 · `plate_fixture` · 기록 · 장신구 고정값 그대로.
- `weapon_fixture.txt`는 한 줄만 — 낫의 콤보(65행)에서 동작 이름 둘(`"attack"` → `"scythe1"`, `"attack2"` → `"scythe2"`). 다른 칸은 같다.
  `WEAPON_FIXTURE_WRITE=1 cargo test weapon_and_class_rows_match_the_weapon_fixture`로 다시 썼다.
- 평타의 휘두르는 쪽 표 `SWEEPS`에 낫 1 · 2타 두 줄(검 1 · 2타와 같은 쪽 · 구간 — 초승달 · 박자 부채꼴의 그림이 전과 같다).
- 시험이 모델에서 다시 잰다: 칼끝이 판정 구간 가운데에 정면을 지나고 표의 쪽으로 가는지(대검 2타는 처음에 −52°로 표의 "왼쪽 → 오른쪽" 60°에
  못 미쳐 판정 구간에 더 담았다, 낫 2타는 칼끝이 −40°라 몸을 돌렸다), 스킬 클립이 정면에서 시작 · 끝나고 판정 순간 정면인지(새 넷 포함).
  "빌린 스킬 동작은 넷" 시험은 "빌린 것이 없다"로 고쳤다.
