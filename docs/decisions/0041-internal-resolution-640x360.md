# 0041. 내부 해상도 480×270 → 640×360, UI 배율은 따로

- 날짜: 2026-11-04
- 상태: 채택(사장: "해상도를 조금 높여야해? 아니면 줌을 더 줘야하나..? 너무 작아서 모션도 잘 안보인다는거야?" → 비교 뒤 "제안대로 하겠어").
- 지금(2026-11-05 결정 검토, 0066 때): 고정 640×360은 0046(`render::fit_internal` — 화면에 맞춘 내부 해상도)이 대신한다.

## 왜
- 0038·0039의 방랑자 동작이 잘 안 보였다: 쿼터뷰 키 약 20px(1px ≈ 7cm, 10% 찌그러짐 = 2px), 위에서 보면 두건이 몸을 덮는다.
- **480×270은 720p에서 정수 배율이 없다**(KB `reference/macroquad/pixel-perfect-rendering.md` 표): 1280×720 창·720p 핸드헬드에서 ×2(960×540)로 둘레 44%가 검었다. 640×360은 720p ×2·1080p ×3·1440p ×4·4K ×6로 꽉 찬다.
- 같은 장면 네 벌을 찍어 비교(지금 / 640×360 / 줌인 거리 15 / 640×360 + 피치 33°): 줌인은 보이는 범위가 25% 줄어 옆의 적이 화면 밖으로 나갔다 → 버림. 피치는 랩으로 판정(`cam.quarter.pitch`).

## 정한 것
1. `INTERNAL_W/H` = 640×360. 카메라·FOV는 그대로라 **보이는 범위는 같고** 같은 것이 1.33배 많은 픽셀로 그려진다(방랑자 쿼터뷰 ≈ 27px, 락온 ≈ 67px). 1080p 화면에서는 물리 크기가 같고 촘촘해지며, 720p 화면에서는 화면을 꽉 채워 커 보인다.
2. **UI 배율을 렌더 배율에서 뗀다**: `Frame::ui` = 렌더 정수 배율 × 360 / `UI_REF_H`(270). UI·HUD는 480×270 기준으로 짠 그대로 — 화면 속 글 크기는 해상도를 올려도 같다(1080p에서 렌더 ×3, UI ×4).
3. 조작 안내 줄(타이틀·멈춤)이 화면 폭(94%)을 넘으면 두 줄로 나누고 메뉴 안내는 그 위로(`Ui::hints`). 예전에도 이 줄은 게임 화면보다 넓었는데 검은 테두리 위로 넘쳐 보였을 뿐, 테두리가 사라지자 창 밖으로 잘렸다.
- `tools/test/touch.js` 타이틀 탭 자리 셈도 640×360·UI 배율로.
