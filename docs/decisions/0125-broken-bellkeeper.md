- 날짜: 2026-11-09
- 상태: **채택·구현**(`release/v0.5`, 상자 단계 — 모델·동작은 0116 차례의 마지막). 0116 표 "둘째 문지기 = 거리·공간형"·이름(사장 2026-11-08)을 그대로 만든 것.
- 스터디: KB `concepts/ranged-boss-for-melee-player`(1차: nail 0052 — 부채꼴 탄 + 되받아치기, 체력 반 아래는 새 동작 대신 **수**, 피해는 표시가 끝나는 순간만, 보스가 사라지면 탄도 사라진다), `concepts/timing-parry`(패링 = 바라보는 쪽 반원).

- 종지기가 쓰러지면 날던 조각도 사라진다(이긴 뒤에 맞지 않게). 화로에서 다시 설 때도 지운다.
- 수치: 체력 46(첫 문지기 40), 반지름 1.0·키 3.0, 걸음 2.2, 잔불 30. 조각 빠르기 9m/s·사거리 14m·반지름 0.35. 값은 `species::BELLKEEPER`·`tuning.rs`(0125 묶음) — 얼린 값(0013)은 건드리지 않았다.

## 기록·보상
- 핵 점수는 따로: `core.bellkeeper`(`Progress::bell_cores`, 셋까지). 나무 마디는 두 문지기 핵을 더한다(`tree_points`). 처음 이긴 판은 "핵이 몸에 스민다" 카드 + 핵이 다가온다(`first_core`). 마을 `boss_charm`은 아직 없음 — C6(장신구 셋, "종지기의 귀")에서.
- 마을 끝의 임시 문지기(0118)를 이것으로 바꿨다 — 이기고 핵을 거두면 판이 끝난다(결과 화면, 0118 그대로).

## 그림(상자 단계)
- 몸은 상자 배우 + 등 뒤에 끄는 청동 종(울림 예고 동안 들어 올린다). 고리는 하나하나 따로 그려 사이가 설 자리로 읽힌다. 조각은 도는 청동 십자 + 꼬리, 되받은 것은 호박빛.
- 헤드리스(2026-11-09): 고리 두 겹·휘두르기 부채꼴·날아가는 조각·돌진 띠가 보인다. 종은 쿼터뷰에서 몸 뒤라 가려지기 쉽다 — 모델 단계에서 종을 옆으로 끌게 볼 것.

## 시험
- `toll_rings_hit_once_each_and_a_jump_clears_them`(고리 둘 = 두 대, 반 아래 셋, 뛰면 0, 9m 밖 0)
- `a_parried_shard_flies_back_and_cuts_the_bellkeeper`(부채꼴 셋·다섯, 패링 → 종지기 −3·플레이어 그대로, 패링 없으면 −1)
- `shards_vanish_when_the_bellkeeper_falls`, `the_bellkeeper_alternates_toll_and_swing_up_close_and_shards_and_charge_afar`
- `bellkeeper_cores_are_kept_apart_and_add_to_tree_points`(save), `the_village_bellkeeper_fights_and_its_core_ends_the_run`(stage)
- 개발: 전투·적 "깨진 종지기"(시나리오 `broken bellkeeper`)

## 판정에서 볼 것(사람)
- 첫 문지기와 다르게 느끼나(Z3): 붙으면 고리, 떨어지면 조각 — 거리를 고르는 싸움인가.
- 고리 사이로 굴러 들어가기·뛰어넘기가 둘 다 쓸 만한가, 2.6m 간격이 좁거나 넓지 않나.
- 조각 되받아치기가 "가장 빠른 공략"으로 읽히나, 3 피해가 너무 세거나 약하지 않나.
- 46 체력 + 마을 등급(잡몹만)과 맞는 길이인가.
