# 0152. 메뉴 장면은 그리는 층에서 끌어온다 — 도감에서 터치가 안 먹던 것

- 날짜: 2026-11-11
- 상태: 결정(고침)
- 사장 2026-11-11: "도감 메뉴에 들어가면 터치가 안 먹어.."

## 무슨 일이었나
`Scene::is_menu()`는 "메뉴 입력을 받는 장면"을 하나씩 적은 목록이었고, 도감(`Scene::Codex`, 0130)이 거기서 빠져 있었다.
앱은 프레임마다 `input.poll(scene.is_menu())`로 터치를 읽는다 — 메뉴면 탭(뗄 때 누름)·끌기, 아니면 싸움 조작(왼쪽 반 = 스틱, 오른쪽 = 버튼).
도감이 메뉴가 아니라고 읽혀 손가락이 스틱·공격 버튼으로 들어갔고, 탭이 생기지 않아 탭·줄·✕가 하나도 안 먹었다.
키보드·패드는 장면 틱이 `Actions`의 메뉴 키를 그대로 읽어서 멀쩡했다 — 그래서 헤드리스(키보드) 시험에 안 잡혔다. 같은 까닭으로 도감에서는 메뉴 소리도 안 났다.

## 왜 생겼나
새 장면을 더할 때 고칠 곳이 둘이었다: `layer()`(`_` 없는 match — 빠뜨리면 컴파일이 안 된다)와 `is_menu()`(`matches!` 목록 — 빠뜨려도 조용하다). 조용한 쪽이 빠졌다.

## 결정
- `is_menu()` = **싸움 화면(`Layer::Game`)이 아닌 모든 장면**. 목록을 따로 두지 않고 `layer()`에서 끌어온다 — 새 장면은 컴파일러가 묻는 한 곳만 고치면 된다.
- 지금 장면 표로는 예전 목록 + 도감과 똑같다(타이틀·창·묻는 창 = 메뉴, 싸움·끝 장면·개발 아레나 = 아님).
- 시험: `flow` 시험에 도감 두 탭·기술 창이 메뉴임을 적었다.

## 확인
헤드리스 Chromium(터치): 도감에서 둘째 탭·셋째 줄·✕를 손가락으로 눌러 탭이 바뀌고·줄이 골라지고·멈춤으로 닫히는 것을 봤다. 실기기는 아직.
