# 0058. 키보드+마우스 — 마우스는 오른쪽 스틱과 같은 일(조준), 땅 돌리기는 남긴다

- 날짜: 2026-11-05
- 상태: **채택·구현**(2026-11-05). 사장: "마우스를.. 어떻게 쓰도록 해야 할까나…?" → "마우스 = 패드의 오른쪽 스틱" 원칙과 추천안(정할 것 다섯 모두)을 보고 "좋아 이대로 진행하자".
- 계기: 사장 2026-11-05 — 소울라이크·ARPG 키보드 배치 조사를 보고 "KB 노트와 마우스 프리셋 제안 둘 다 진행", "마우스 사용할 때는 화면 90도 회전하는 기능은 필요없겠지".
- 근거: KB `concepts/keyboard-and-mouse-layout-for-action-games.md`(게임별 기본 키는 모두 2차 출처), `concepts/controller-layout-and-remapping.md`, 0024·0028·0029·0048·0055·0056.

## 지금 무엇이 모자라나
- 키보드 배치(0024·0048)는 마우스 없이 양손을 키보드에 둔다: 왼손 WASD·Space 회피·F 점프·R 등잔·Q/E 땅 돌리기, 오른손 J 공격·K 패링·L 락온·U 마법. 조사한 PC 액션 게임은 모두 마우스를 쓴다(소울라이크 = 왼쪽 클릭 공격·휠 클릭 락온, Hades II = 왼쪽 클릭 공격·오른쪽 클릭 특수).
- **키보드에는 손으로 겨누는 입력이 없다.** `input.rs`의 `aim`은 패드 오른쪽 스틱(데스크톱·Android)에서만 채워진다. 키보드로는 마법(0048)·모은 탄(0056)·수류탄 겨누기(0055)가 자동 조준·바라보는 쪽뿐이다.

## 땅 돌리기는 마우스에서도 남긴다
사장의 말("마우스면 90° 회전은 필요 없다")은 **마우스가 카메라를 돌릴 때만** 맞다. 이 게임 쿼터뷰에서는 마우스가 카메라가 아니라 조준을 맡는 쪽을 권한다. 이유는 셋이다.
1. **땅 돌리기는 시점 바꾸기이면서 싸움 동작이다.** 몸이 90° 돌아서고(0028), 8m 안의 적을 짧게 휘청이게 하고(0029), 대기 4초, 후딜레이를 끊는 자리(0057)가 있다. 마우스 카메라는 시점만 대신한다. 마우스 플레이어만 이 동작을 잃으면 **장치에 따라 규칙이 갈린다**(concept: "규칙은 하나, 모드마다 다른 것은 카메라·타깃팅·입력 기준뿐").
2. **마우스 움직임은 한 가지 일만 맡을 수 있다.** 카메라를 돌리면 조준을 잃는다. 고정 카메라 탑다운 게임(Hades II·Diablo IV·PoE 2)의 기본 키에는 카메라 돌리기가 없고, 마우스는 조준·대상에 쓴다(2차). 이 게임은 키보드에 조준이 없는 것이 지금 더 큰 구멍이다.
3. **Q·E는 마우스를 쥐어도 왼손 검지에 그대로 닿는다.** 마우스가 오른손을 가져가도 땅 돌리기 키는 비켜날 이유가 없다.
- 락온 숄더뷰(0040·0050)는 카메라를 대상이 정한다. 마우스 움직임은 아무것도 하지 않는다(소울라이크 관례인 "마우스를 휙 = 대상 바꾸기"는 대상 바꾸기 자체가 아직 없어 나중에).
- 하지 않는 것: 쿼터뷰 마우스 자유 회전, 포인터 잠금(커서 조준에는 필요 없다).

## 배치안
| 동작 | 키보드만(지금, 0024·0048) | **키보드+마우스(새 프리셋)** | 근거 |
|---|---|---|---|
| 이동 | WASD·화살표 | WASD | 고정 |
| 공격(꾹 = 강타, 0030) | J | **왼쪽 클릭** | 모든 조사 게임 |
| 마법·사격(꾹 = 모으기, 0056) | U | **오른쪽 클릭**(커서 쪽) | Hades II 특수 = 오른쪽 클릭, 0048 "겨누며 누를 버튼은 조준 장치와 같은 손" |
| 수류탄(원거리 무기의 X, 0048·0055) | J | 왼쪽 클릭(커서 자리로) | 무기 표의 X 칸 그대로 |
| 패링(0025) | K | **L-Shift** | P의 거짓 막기 = Shift(2차). 마우스 옆 버튼은 miniquad가 받지 못한다 |
| 락온 | L | **휠 클릭** | 조사한 소울라이크 다섯 모두 |
| 회피 | Space | Space | 대세(세키로만 Shift) |
| 점프 + 상호작용(0048) | F | F | 엘든 링 점프 F |
| 등잔 | R | R | 소울라이크 회복 R |
| 땅 돌리기 | Q·E | Q·E | 위 "남긴다" |
| 메뉴 확인·뒤로·멈춤 | Enter·Esc | 그대로 | 고정 |

- 조준점: 커서를 땅 평면(플레이어 발 높이)에 비춘 점. 쓰는 순서는 지금 규칙(0014·0048)에 커서를 끼운다 — 락온 대상 > **최근 1초 안에 움직인 커서** > 자동 조준 > 바라보는 쪽. 커서가 쉬면 자동 조준으로 돌아간다(Hades 원작의 "커서를 숨기면 가까운 적"과 같은 생각, 유저 보고).
- 커서 자리에 작은 조준 표시를 그린다(마법 겨누는 동안만 선 + 점).
- 프리셋은 키 칸만 바꾼다. 패드 칸·다시 붙이기(0024)는 그대로이고, 프리셋 안에서도 다시 붙인다(마우스 버튼도 붙일 수 있는 칸).

## 마우스 감도
사장 2026-11-05: "마우스가 들어간 이상, 마우스 감도에 대한 설정도 추가되어야 함."
- 감도 = 마우스가 **움직인 양(상대값)**에 곱하는 배율이다. 무엇에 곱하는지가 정해져야 칸이 뜻을 갖는다.
- **커서 조준(이 제안)에서는 곱할 곳이 없다.** 커서는 OS 커서(절대 위치)라 빠르기는 OS 설정·마우스 DPI가 정한다. 게임이 배율을 곱하면 화면의 커서와 겨누는 자리가 어긋난다. 조사한 커서형 ARPG(Diablo IV)에는 감도 칸이 보이지 않고, 대신 커서 크기·색·잘 보이기 칸이 있다(2차). Hades II는 감도 칸이 있다는 글이 하나 있지만 확인하지 못했다.
- 감도 칸을 넣으려면 **가상 커서**(포인터 잠금 + 게임이 그리는 커서)로 가야 한다. macroquad 0.4.16에 `set_cursor_grab`·`mouse_delta_position`이 있고 웹 번들도 `movementX`를 넘긴다(코드 확인). 비용:
  - 웹은 클릭(사용자 제스처) 뒤에만 잠기고, **Esc가 늘 잠금을 푼다**(MDN Pointer Lock API). 우리 Esc = 멈춤과 겹친다(그때 게임에 Esc가 들어오는지는 아직 안 봤다).
  - 커서를 게임이 그리니 하드웨어 커서보다 한 프레임쯤 늦다.
  - 메뉴는 커서 없이 움직이므로(0042) 메뉴에서는 문제가 없다.
- **감도가 꼭 필요해지는 때**:
  - 정할 것 1에서 마우스 카메라를 고르면 감도는 필수다. 칸은 가로·세로 감도와 세로 뒤집기. 엘든 링은 마우스 감도와 카메라 속도를 따로 둔다(2차).
  - 나중에 락온 대상 바꾸기(마우스를 휙)를 넣으면, 몇 픽셀을 움직여야 바뀌는지(문턱)가 그 감도다.
- 안:
  - **A(추천)**: 지금은 감도 대신 "마우스 조준" 칸 셋 — **조준 표시 크기**, **커서 쉼 시간**(자동 조준으로 돌아가기까지, 기본 1초), **마우스 조준 켬/끔**. 감도 칸은 마우스 움직임을 상대값으로 쓰는 기능(대상 바꾸기·마우스 카메라)과 함께 넣는다.
  - B: 가상 커서 + 감도(0.25~4배, 로그 눈금, 기본 1), 웹은 `unadjustedMovement`(가속 끄기)를 먼저 시도. 위 비용을 진다.
- 어느 쪽이든 prefs 칸은 뒤에 붙인다(MAGIC 그대로).

## 구현할 것(제안 때 적은 것 — 실제는 아래 "구현")
- 입력: 키 칸 표 `KEYS` 뒤에 마우스 버튼 셋(왼쪽·오른쪽·가운데)을 붙인다. 옛 번호의 뜻이 바뀌지 않으니 prefs 칸은 뒤에 "프리셋" 칸 하나만 붙인다(MAGIC 그대로 — 옛 저장은 0 = 키보드만).
- 조준: `Actions::aim`을 커서에서 채운다. Camera3D 역행렬로 광선 → 땅 평면. 월드는 `Basis`·`Actions`만 보고 그대로.
- 장치: 마우스를 움직이거나 누르면 "키보드" 장치로 센다. 단 웹 모바일 브라우저는 터치마다 가짜 마우스 이벤트를 만들 수 있다(KB) — 터치 장치일 때는 세지 않는다.
- 안내: `input::prompt`가 마우스 칸 이름(왼쪽 클릭·오른쪽 클릭·휠 클릭)을 i18n 표에서 읽는다. 새 글자가 있으면 글꼴 서브셋(`tools/fonts/subset_ui.py`).
- 웹: 캔버스에서 오른쪽 클릭 메뉴(`contextmenu`)·휠 클릭 자동 스크롤을 막는다. 번들에는 막는 코드가 없다(grep, 실제로 뜨는지는 아직 안 봤다). 번들은 고치지 않고 `web/index.html`에서.
- 조작 설정(0052): 맨 위에 "배치: 키보드만 / 키보드+마우스" 줄.
- 시험(안): `the_mouse_preset_moves_only_the_key_column`, `a_recently_moved_cursor_aims_and_a_resting_one_falls_back_to_auto`, `turning_works_the_same_in_both_presets`, `old_prefs_read_as_keyboard_only`. 헤드리스 Chromium으로 오른쪽 클릭 마법이 커서 쪽으로 나가는지.

## 함께 본 것(이 결정 밖)
- miniquad 0.4.11은 Linux X11·Wayland에서 키를 배열의 글자로 받는다(웹·Windows·macOS는 위치, KB 노트). PC 묶음을 Linux로 내면 AZERTY에서 WASD가 흐트러질 수 있다. 패치는 나중.

## 정한 것(사장 2026-11-05, 추천안 그대로)
0. **원칙: 마우스는 패드의 오른쪽 스틱과 같은 일을 한다.** 오른쪽 스틱은 쿼터뷰에서 조준만 하고, 락온 중엔 쓰지 않고, 어느 장치로도 카메라를 자유롭게 돌리지 않는다 — 마우스도 그렇다. 장치가 달라도 규칙이 하나(concept). 클릭 이동·마우스 카메라는 고르지 않았다.
1. 땅 돌리기: 마우스 배치에서도 Q·E로 남긴다.
2. 패링 키: L-Shift.
3. 새로 설치한 판의 기본: 키보드+마우스. 이미 저장한 배치는 그대로 읽는다(설정을 한 번이라도 저장한 브라우저·PC는 키보드만 배치가 남는다 — 조작 설정에서 "키보드+마우스 배치로").
4. 락온 중 "마우스를 휙 = 대상 바꾸기"는 대상 바꾸기를 넣을 때 패드 오른쪽 스틱과 함께. 그때 문턱이 감도다.
5. 마우스 감도: 안 A — 감도 칸 없이 마우스 조준 칸 셋(켬/끔·커서 쉼 시간·조준 표시 크기).

## 구현(2026-11-05)
- 배치표: 키 칸 번호 = `KEYS`(30) 뒤에 마우스 버튼 `MICE`(왼쪽·오른쪽·가운데, 이름 LMB·RMB·MMB — ASCII), `input::Slot`이 키/마우스를 가른다. 옛 번호의 뜻은 그대로라 prefs `MAGIC`은 그대로. `Bindings::default_layout()` = 키보드+마우스, `keyboard_only()` = 0024·0048 배치(패드 칸은 같다). 조작 설정의 "기본값으로" 한 줄 → "키보드+마우스 배치로"·"키보드만 배치로" 두 줄. 키보드 칸은 마우스 버튼 눌림도 받는다.
- 커서 → 조준: 입력이 "최근 만진 커서"만 `Actions::cursor`로 넘기고(`input::cursor_live` — 마우스 조준 켬 + 장치가 키보드 + 만진 지 쉼 시간 안, 2px 넘게 움직이거나 누르면 "만졌다", 터치 뒤 1초는 흉내 낸 마우스로 보고 세지 않는다), 앱이 지난 프레임 화면 자리로 NDC → `camera::screen_ray`(리그, 흔들림 빼고) → 플레이어 발 높이 면 `ground_hit` → `Actions::aim_at`. 월드는 오른쪽 스틱 자리에서 그 점 쪽을 겨눈다(0.5m 안이면 겨누지 않음, 락온이면 무시). 커서는 자리까지 주므로 수류탄(톡·꾹)은 그 자리로(2m..먼 거리).
- 그림: 싸움 중 마우스 조준이면 OS 커서를 숨기고 조준 표시(고리 + 점, 어두운 테두리, 붉은색 아님)를 커서에. 락온 중·쉬는 커서는 그리지 않는다.
- 설정: 마우스가 있을 법한 기기(Android·손가락 브라우저 아님)에만 줄 셋 — 마우스 조준 켬/끔, "커서가 멈추면 자동 조준: {0}초"(0.5·1·2·4, 기본 1), 조준 표시(작게·보통·크게). 줄이 여덟이 되어 설정 화면은 제목·메뉴를 올리고 줄 간격을 안내 위까지로 줄인다(`Ui::menu_in`). prefs 칸 22..25(0 = 기본값).
- 메뉴: 왼쪽 클릭을 뗄 때 탭(터치와 같은 규칙). 웹 `index.html`이 캔버스의 오른쪽 클릭 메뉴·휠 클릭 자동 스크롤을 막는다.
- 글꼴: 새 글자(우·켬 등)로 UI 서브셋을 다시 만들었다(원본 고운바탕 2.000은 Google Fonts API에서).
- 시험: `a_recently_touched_cursor_aims_and_a_resting_one_falls_back_to_auto`, `mouse_buttons_follow_the_keys_in_the_slot_numbers`, `the_cursor_point_aims_like_the_right_stick_and_lock_on_ignores_it`, `a_tossed_grenade_lands_at_the_cursor`, `the_mouse_preset_moves_only_the_key_column_and_keeps_the_turn`, `mouse_slots_and_mouse_aim_cells_round_trip`, `the_screen_centre_hits_the_look_point_and_up_is_farther`, `a_ray_above_the_horizon_hits_nothing`, 설정 줄. 헤드리스 `tools/test/mouse.js`(빈 방에서 커서 오른쪽·왼쪽 + 오른쪽 클릭 → 탄이 커서 쪽, 조준 표시, 휠 클릭 락온, 브라우저 기본 동작 막힘), `shot.js`·`leak.js`는 처음에 "키보드만 배치로"를 고른다. 영어 설정·조작 화면 F4 넘침 검사 깨끗.
- 아직: 실제 마우스·사람 손으로는 안 해 봤다.
