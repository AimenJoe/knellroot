# 0002. PoC → Lab → Game 세 축, 그리고 첫 커밋에 깐 규칙

- 날짜: 2026-11-03
- 상태: 채택(사장: "PoC 및 lab을 기본으로 시작", "기존 knowledge base를 활용하거나 업데이트")

## 결정
- 하나의 레포, 하나의 실행 파일. **모드가 아니라 시나리오 + 랩 패널**로 PoC와 Lab을 한다(ChatGPT의 Game/Poc/Lab 모드 분리는 로직 복제를 부른다). 운영판은 `--no-default-features`로 시나리오 전환·랩을 뺀다.
- PoC는 질문·통과 기준·상한·대안이 있는 표(`phase-0-poc.md`). 통과한 것만 Game으로.
- Lab은 `tuning.rs`의 `SPECS` 표를 실행 중 바꾸고 A/B·export(`docs/lab.md`). 게임은 저장 파일을 읽지 않는다.
- 첫 커밋에 깐 규칙(KB `guides/second-game-project-day-one.md`의 15개 중 지금 해당하는 것): `Actions`만, 고정 틱 + 보간, 수치 한 곳, 로직에 부작용 핸들 없음(소리는 아직 없지만 들어오면 큐), 틱 단계 메서드, 시나리오 표, 결정 기록, CI(fmt·clippy 둘·test·wasm·스크린숏), 라이선스 파일, dev feature. 글 표(i18n)·안내·저장은 플레이어가 보는 글·기록이 생길 때.

## 왜
첫 게임의 리팩터링 기록(0169·0170·0230·0248)은 전부 "규칙을 늦게 깐 값"이었다. 반대로 뼈대가 게임보다 커지면 첫 플레이어블이 늦는다 — 그래서 파일 하나·함수 하나 수준에서 멈췄다(모듈 일곱, 1,500줄 안팎).

## 확인
`cargo test` 12개(규칙 시험), 시나리오 넷 600틱 시험이 "로직이 부작용 핸들을 안 받는다"의 증거.

## 다시 볼 조건
랩이 세 개를 넘어 유지비가 보이면 정해진 값의 랩을 지운다. 플레이어 글이 생기면 i18n 구조를 그날 깐다.
