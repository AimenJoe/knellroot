# 0053. 터치 배치: 공격 둘레 호, 상황 버튼, 돌리기 캡슐

- 날짜: 2026-11-04
- 상태: 채택·구현(사장: "타치스크린에서의 버튼 배치도 공부해보자.. 너무 난잡하잖아?")

## 왜
- 0006에서 nail 틀(버튼 여섯)로 시작했다. 그 뒤 0025 패링, 0027 점프, 0031 등잔, 0032 상호작용, 0048 마법을 하나씩 덧붙여 싸울 때 버튼이 10개(개발판은 12개)가 됐다.
- 0048에서 패드는 점프와 상호작용을 합쳤는데, 터치에는 모닥불 버튼이 따로 남아 있었다.

## 근거
1차:
- Apple HIG "Game controls"(2025-06 개정)
  - 자주 쓰는 컨트롤은 44pt 이상, 덜 쓰는 것은 28pt 이상.
  - "쓸 수 없거나 상관없으면 숨겨 어수선함을 줄여라", 여러 동작은 한 컨트롤로.
  - 버튼 그림은 글자가 아니라 기호로.
- Apple HIG "Accessibility": 테두리 있는 요소 둘레에 약 12pt를 둔다.
- Android 도움말: 48dp, 간격 8dp 이상.
- Activision 블로그(CoD Mobile 2019): 상황 버튼 — 문 앞에서는 문 열기, 장애물 앞에서는 점프가 넘기.

2차:
- Diablo Immortal·Wild Rift·Brawl Stars: 공격이 가장 크고 그 둘레에 스킬이 놓인다.
- Fez(Vita): 쓸어서 세계를 돌린다.

## 정한 것(`touch::layout`, 기준 u = 짧은 변, 상한 520)
- **늘 보이는 것**: 공격(지름 0.27u, 오른쪽 아래)과 그 둘레 첫째 호(거리 0.26u).
  - 회피(188°) · 패링(146°) · 마법(104°) · 점프(62°). 각도는 180° = 왼쪽, 90° = 위.
  - 자주 쓰고 타이밍이 중요한 것일수록 엄지를 굴리면 닿는 자리에 둔다.
- **점프 = 상호작용**: 쉼터 곁에서 안전하면 같은 버튼이 모닥불 그림으로 바뀌고 쉬기를 한다. 따로 있던 모닥불 버튼은 없앴다(패드 0048과 맞춤).
- **둘째 호(0.44u)**:
  - 땅 돌리기 둘을 **캡슐 하나**로 묶었다(118°). 왼쪽 반 = 왼쪽, 오른쪽 반 = 오른쪽.
  - 상황 버튼:
    - 락온(80°): 락온 거리 안에 깨어 있는 적이 있거나 이미 락온 중일 때만.
    - 등잔(150°): 체력이 가득이 아니고 등잔이 남았을 때만.
  - 상황 버튼은 **비워 둔 제 자리에만** 뜨고 다른 버튼을 밀지 않는다(시험 `contextual_buttons_never_move_the_others`).
- 싸울 때 버튼 수: 10~12개 → 7개 + 상황 버튼 0~2개.
- 개발판 랩 줄은 0.21u 높이로 올렸다(작은 폰에서 돌리기 캡슐과 겹쳤다).
- 시험:
  - 겹침 없음·화면 안(폰·작은 폰·태블릿·데스크톱·세로 폰, 상황 버튼을 다 켠 채).
  - 공격이 가장 크고, 가장 작은 버튼도 최소 크기(44pt) 이상.
  - `tools/test/touch.js`의 `layout()`도 같은 식으로 고쳤다.

## 나중에(사장 판정 뒤)
- 쓸어서 돌리기(캡슐은 그대로 두고 제스처를 더함).
- 마법을 꾹 눌러 끌어 조준.
- 설정에 버튼 크기·불투명도·왼손 뒤집기, 그다음 끌어 옮기는 편집기.
- iPhone safe area(웹 `env(safe-area-inset-*)`)는 확인하지 못했다.
