# 0101. 세계관 바이블 — 이야기 방향 셋·상태 넷·`docs/lore/`

- 날짜: 2026-11-07
- 상태: **방향 셋은 채택**(사장 2026-11-07, ChatGPT 설계 대화에서 "1. 미스터리 깊이: 천천히 공개 / 2. 이야기 전달: 혼합 / 3. 엔딩: 큰 방향만 확정 — 이 방향으로 세계관 바이블 설계를 시작해줘"). 바이블 본문(`docs/lore/`)은 **제안**이 기본이고, 아래 "사장이 정한 것"(2026-11-07 인터뷰)만 CANON.
- 근거: 0004(D2 = a·열린 질문 여섯), 0037(색 = 생명, 그림 쪽 이야기 안은 제안), 0069(보라 뿌리·둘째 구역·포포 고리 — v0.5.0으로 옮김), 0095·0096(v0.4.0 성장), 게임 글 `src/i18n/ko.rs`. 대화 요약 `docs/research/chatgpt-2026-11-07-lore-bible.md`.
- 스터디: KB `roguelite-narrative-delivery`(큰 사실은 환경으로·이름표가 가장 세게 드러낸다·원인과 결과를 한 문장에 묶지 않기), `cute-characters-in-a-dark-world`. 바깥(2차): Smith·Worch GDC 2010 "What Happened Here?"(환경 서사 = 플레이어가 흩어진 것을 이어 완성), 서사 문서 글들(정본을 한곳에, 잠정 사실은 잠정이라 표시, 끝까지 고쳐 쓰는 바이블).

## 왜
- 시스템 결정(0001~0100)은 쌓이는데 이야기의 인과는 비어 있다(0069 "세계관이 비어 있어 그림·적·이름을 못 만들었다"). 둘째 구역(v0.5.0) 전에 **무엇을 정했고 무엇을 일부러 안 정했는지**를 한곳에 둔다.
- "천천히 공개 + 엔딩 큰 방향만"은 단서를 먼저 놓고 진실을 나중에 정하는 길이라, 놓은 단서가 나중 진실과 부딪힐 위험이 가장 크다 → 상태 넷으로 가르고, MYSTERY에 단서를 놓을 때는 **남은 후보 답 모두와 맞는지** 본다.

## 무엇을
1. 방향 셋(위) — `docs/lore/README.md` 첫머리.
2. **상태 넷**: CANON(정함, 바꾸려면 새 번호) · PROPOSED(제안, 사실처럼 쓰지 않음) · MYSTERY(의도한 수수께끼, 개발자 답도 아직 없음) · OPEN(필요할 때 정함). **게임에 나간 글은 CANON**이다.
3. 자리: `docs/lore/`(README = 입구, `ecology.md`, `growth.md`). 결정은 여기 `docs/decisions/`, 시스템은 `docs/design/`·결정, 세계관 요약은 `concept.md`가 링크.
4. ChatGPT 안을 레포와 맞춰 고친 것:
   - 종: "종을 보여 주지 않는다" → 성소에는 보이는 종(`L`)·"성소의 종을 치던 망치"가 이미 있다. **울리는 종(근원)을 보여 주지 않는다**로(0069 "울리는 종은 더 아래"와 같다).
   - 순례자: 무기 글의 "순례자"가 이미 나갔다 → 떠난 자들의 때의 흔적으로 적음.
   - "뿌리 ≠ 침식"은 `intro_2`("뿌리가 닿은 곳마다, 죽은 것이 일어선다")를 관찰로 읽어 유지 — 보편 인과로 넓히지 않는다.
   - 색: 0037 그림 규칙이 우선, 그 위에서 "뿌리 색 하나 = 기능"의 일대일 규칙만 만들지 않는다.
   - 방랑자와 포포: ChatGPT는 MYSTERY로 적었으나 0069 정할 것 3(PROPOSED)이다.
   - 나무 칸 이름: "가벼운 발"이 장신구 이름과 겹침, 모으기 패링·땅 돌리기가 빠짐 → `growth.md` 4에 표시. 칸 내용은 0095 초안이 기준.
   - 첫 구역 "좁은 길"은 게임 구역 이름이 아니다 → 입구와 뜰 사이 길로.
