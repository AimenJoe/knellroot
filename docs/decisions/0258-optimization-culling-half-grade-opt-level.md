# 0258 — 최적화 1차: 재는 도구 · 시야 밖 거르기 · 2배일 때 마무리는 반 크기에서 · opt-level 3

- 날짜: 2026-11-19
- 상태: 채택(개발판 — 기기 판정 전, 체크리스트 100)
- 사장: "다음은.. 최적화야" (v0.7.3 배포 뒤)

## 먼저 잰 것(왜 이 넷인가)
재기 전에 짐작으로 고치지 않으려고 구간 시간 재기를 먼저 넣었다(아래 1). PC 리눅스 개발판을 가상 화면(Xvfb + llvmpipe — GPU를 CPU로
흉내 내는 소프트웨어 GL이라 절대 ms는 기기 숫자가 아니다, 구간끼리의 비만 본다)에서 정원(`KNELL_BOOT=Garden`)·부하 80으로 돌렸다.

| 구간(정원, 1280×720, 프레임당 ms) | 거르기 전 | 거르기 뒤 |
|---|---|---|
| 적 | 4.9 | **0.5** |
| 지형(상주 버퍼 + 배치) | 11.5 | 8.4 |
| 법선 패스(선 긋기용 다시 그리기) | 11.8 | 8.3 |
| 옅은 덩어리·입자·아지랑이 | 5.0 | 2.5 |
| 그리기 합 | 55 | 43 |
| fps(llvmpipe) | 14 | 18 |

- **까닭 하나: 시야 거르기가 없었다.** 지도 전체의 적(정원 40마리)과 지형 덩어리(≈ 35만 정점)를 카메라와 상관없이 프레임마다 그렸다.
  적은 마리마다 CPU에서 자세 → 정점 빛 셈 → 그림자 가림판 → 외곽선 껍데기 → 법선 패스 기록까지 한다.
- **까닭 둘: `opt-level = "z"`(크기 우선).** 첫 커밋부터의 값이고 결정 기록이 없다. 같은 장면에서 `3`이면 우리 코드의 계산 구간이 빨라졌다
  (부하 80: 틱 0.60 → 0.38ms · 방랑자 0.71 → 0.49 · 소품 0.42 → 0.13).
- 남은 큰 몫은 GPU 일(llvmpipe에서는 메인 스레드가 그 몫을 기다린다 — gdb 표본의 약 75%)과 macroquad가 정점을 자기 버퍼로 옮기는 일
  (`QuadGl::geometry`)·정점마다의 빛 셈(`bake_glow`) — 둘 다 **그리는 정점 수에 비례**해서 거르기가 같이 줄인다.

## 정한 것
1. **구간 시간 재기 `src/prof.rs`**(개발판 PC만 — 웹·운영판은 빈 함수): `let _p = prof::span("이름")`, 환경 변수 `KNELL_PROF=<초>`면 그 초마다
   구간별 프레임당 평균·최대 ms와 엔진(`next_frame`) 몫을 표준 오류로. 재기용 바로 시작 `KNELL_BOOT=<개발 창 줄 이름>`(`Garden`·`Scenario(Stress80)` …),
   연구소 값 `KNELL_LAB=render.cull=0,…`, 창 크기 `KNELL_WINDOW=1920x1080`. 예:
   `KNELL_PROF=6 KNELL_BOOT=Garden KNELL_WINDOW=1920x1080 xvfb-run -a target/release/knellroot`
2. **시야 밖 거르기 `render/cull.rs`**(순수 — 시험 셋): 카메라 행렬에서 여섯 면(`Frustum::from_matrix`)을 뽑아 구·상자를 본다. 늘 넉넉하게
   (면 밖으로 완전히 넘어간 것만 뺀다).
   - 지형 덩어리: 굽는 때 덩어리마다 상자 `Scenery::bounds`(정점 범위 + 바람에 흔들리는 몫 `SWAY_PAD` 0.6m). 배치로 가는 덩어리·옅은 덩어리는 상자로 거른다.
   - 상주 지형(0186): 묶음을 텍스처만이 아니라 **땅 칸**(`resident::CELL_M` 12m)으로도 나눠 묶음마다 상자를 두고, 색·법선 패스 둘 다 거른다
     (그리기 호출은 조금 는다 — 칸 × 텍스처).
   - 적: 몸 높이만 한 구 + `ENEMY_CULL_PAD` 3m(달빛 그림자 가림판·밀림·큰 몸짓). 거른 적은 자세·빛·외곽선·법선 기록을 다 건너뛴다.
   - 연구소 `render.cull`(기본 1, 0 = 옛 길) — 같은 판에서 A/B. 켬/끔 스크린숏 차이는 흔들리는 풀 끝·떠다니는 입자뿐(찍은 순간의 차이).
3. **2배로 그릴 때(0191 SSAA) 마무리는 줄인 뒤에**: 마무리 셰이더는 화소마다 텍스처를 ≈ 26번 읽는다(선 9 + 번짐 16). 전에는 그것을 두 배 타깃
   (1080 화면이면 1920×1080) 전체에 돌렸다. 이제 첫 패스(두 배)는 **선만**, 번짐·톤·가장자리 어둡게는 반으로 줄이는 패스에서(같은 셰이더의
   둘째 재질 `grade_mat` — 2:1 선형 읽기라 이웃 읽기도 2×2 평균). 번짐 반지름은 그대로 내부 px 단위. 같은 장면 스크린숏 차 평균 1.3/255.
   2배가 꺼진 화면(배율 1)은 그대로.
4. **`opt-level = 3`**: 웹 파일 8.31 → 9.21MB(gzip 4.32 → 4.56MB, +5%). 계산 몫이 30~60% 줄어드는 값에 견주면 싸다. Android·PC·iOS도 같은 프로필.

## 바꾸지 않은 것
- 기본값(얼린 값 0013)은 그대로 — 새 스위치 `render.cull` 한 줄만 붙였다(켬이 옛 그림과 같다).
- 540줄 + 2배(0191)는 그대로 — 사장 판정("느려지지 않음")을 받은 값.

## 남은 것(다음 차례 후보 — 기기에서 재 본 뒤)
- **기기에서 A/B**(체크리스트 100): Android 개발판 → 개발 창 "성능 줄 켬" → 연구소 `render.cull` 0 ↔ 1로 fps·frame을 견준다.
- 적의 정점 빛 셈을 GPU로(셰이더) 옮기기 — CPU에서 정점마다 빛·달그늘을 셈해 프레임마다 다시 올린다. 큰 일이라 기기 숫자를 보고.
- 먼 적의 간단한 몸(LOD)·외곽선 껍데기 생략 — 쿼터뷰에서 멀리 있는 적은 몇 px.
- 상주 지형의 칸 크기(12m)는 재 본 값이 아니다 — 그리기 호출 수와 거른 정점 수를 보고 고른다.
