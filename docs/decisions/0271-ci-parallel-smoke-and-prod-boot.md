# 0271 — 웹 파이프라인: 헤드리스는 나란히, 화소는 적게, main은 나가는 것을 띄워 본다

  개선안에 "응 … 빌드환경의 시스템 스펙도 중요할듯 병렬로 돌릴려면. 진행해".

## 잰 것(고치기 전)
- main 배포(v0.8.1) `build` 잡 약 22분: 준비·Rust·캐시 30초 · fmt + clippy 셋 14초(캐시 적중) · `cargo test` 24초 · wasm 43초 ·
  개발판 wasm 한 번 더 41초 · **shot 7분 06초 · touch 8분 18초 · save 2분 56초 · pwa + away 37초**. 개발판 push는 약 12분 가운데 헤드리스 9분 48초.
  → Rust 쪽은 이미 빠르다(sccache·nextest·mold는 병목이 아닌 곳). **시간의 85%가 헤드리스.**
- 스크립트의 고정 대기는 합쳐도 작다(shot 44초 · touch 16초). 나머지는 **프레임을 기다리는 시간** — 누름 하나가 게임 프레임 둘.
- 헤드리스 Chromium은 GPU 없이 소프트웨어 GL(SwiftShader)로 그린다. 1280×720 화면이면 내부 타깃 1280×720(줄 수 540 → 배율 1)에
  2배 그리기(0190)가 얹혀 패스마다 2560×1440. 같은 기계에서 화면만 줄여 재니: 1280×720 싸움 3.3 fps·스크린숏 2.0초 →
  640×360 8.8 fps·0.74초 → 320×180 18 fps·0.42초. **화소 수가 곧 시간.** Chromium 플래그(`--use-angle=swiftshader` 등)는 이득 없음.
- 러너(GitHub 문서, 2026-11-24 확인): 공개 레포의 `ubuntu-latest` = **잡마다 4 vCPU · 16GB VM 하나**, 무료 계정 동시 20잡(macOS 5).
  SwiftShader는 코어를 다 쓴다 — 한 러너에서 스크립트 둘을 나란히 돌리면 서로 깎아 먹는다(이 컨테이너 4코어에서 시험 셋이 겹치니 부하 10 안팎,
  같은 스크립트가 두 배 넘게 걸렸다). **나란히 = 잡을 나눈다**(잡마다 제 VM).

## 정한 것
1. **싸게 그리기**(시험 깃발 8 — 개발판만, `sceneKit.cheap`): 월드 줄 수 270 · 2배 그리기 끔 · 메뉴 그림 화면 해상도 끔. 화면 크기·UI 배치·터치 자리는
   그대로다. 흐름·기록·터치만 보는 스크립트(touch·save·away·hearth·items·tabs·shield·tutorial·view·mouse)에 건다. 그림을 보는
   `shot.js`·`fx.js`·`menu_res.js`·`leak.js`·`prologue.js`는 제 화질. `FULL=1`이면 걸지 않는다.
   잰 것(같은 기계·같은 부하): 싸움 3.1 → 9 fps, 스크린숏 2.1 → 0.7초, `save.js` 173 → 78초.
2. **잡을 나눈다**: `compile`(fmt·clippy·test·wasm·조립·Cloudflare dry-run) → `smoke`(매트릭스 — shot · touch · save · pwa+away, 잡마다 러너 하나)
   → `build`(문지기 — 앞의 둘이 다 success여야 초록, 그 뒤에 개발판·PR 미리보기 올리기) → `publish`(main).
   main 룰셋의 필수 검사 이름은 그대로 `build`다. 문지기는 `if: !cancelled()`로 늘 돈다 — 건너뛴 필수 검사는 통과로 읽히기 때문.
   벽시계는 "스크립트의 합"에서 "가장 긴 스크립트(shot)"로 준다.
3. **main은 실제로 나가는 운영 빌드를 띄워 본다**: 지금까지 main은 개발판을 한 번 더 빌드해 긴 시나리오를 다시 돌렸고, 정작 배포되는
   `--no-default-features` 빌드는 한 번도 띄워 보지 않았다. main의 smoke는 `boot`(운영 빌드가 타이틀까지 · 타이틀 끝 줄이 설정 = 개발 메뉴가
   안 실렸다 · 새 판이 열려 몇 초 돈다 · 콘솔 에러 없음, `tools/test/boot.js`) + `pwa` 하나뿐. 긴 시나리오는 main에 들어오는 PR의 검사
   (개발판 빌드)에서 이미 돌았다 — main에는 PR로만 들어온다(0092).

## 하지 않은 것
