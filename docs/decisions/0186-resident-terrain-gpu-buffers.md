# 0186 — 상주 지형: 움직이지 않는 지형은 GPU 버퍼에 한 번만 올린다(macroquad 위에서 miniquad를 직접)

- 날짜: 2026-11-14
- 상태: 채택(개발판 — 기기 A/B 판정 전, 체크리스트 41)
- 사장: "그리기 모아서 그리는 것, macroquad 쓰는 것보다 miniquad 직접 쓰는 게 성능이 더 좋아?" → Claude 답(통째로 바꾸지 말고, 매 프레임 다시
  올리는 지형만 직접) + 제안(먼저 재고, 크면 섞어 쓰기) → "응 제안대로 해보자".

## 왜
- macroquad는 GPU에 머무는 메시가 없다: `draw_mesh`는 부를 때마다 정점을 배치에 넣고 프레임 끝에 `buffer_update`로 다시 올린다
  (0.4.16 `quad_gl.rs` `draw`, KB `reference/macroquad/3d-rendering.md`). 구운 지형도 프레임마다 배치로 복사(`Batch::raw`)되고,
  법선 패스(0061)에 쓰려고 한 번 더 복제·업로드됐다.
- 잰 것(정원, 굽기 직후 덩어리 통계): 빛 지도 바닥 58덩어리·72k 정점 · 가리지 않는 덩어리 570개·175k · 가리면 옅어지는 덩어리 581개·44k.
  움직이지 않는 둘(바닥 + 가리지 않는 것)이 **85%**. 정점 하나 40바이트(위치·UV·색·법선).

## 정한 것
- macroquad를 버리지 않는다. 그 아래 miniquad를 `get_internal_gl()`로 직접 불러(이미 외곽선·마무리 재질이 쓰는 길) **움직이지 않는
  덩어리만** 지역에 들어설 때 `BufferUsage::Immutable` 버퍼로 한 번 올린다(`render/resident.rs`). 같은 텍스처끼리 u16 한도 안에서
  이어 붙인다(`resident::plan` — 순수, 시험).
- 그릴 때: 쌓인 macroquad 그리기를 먼저 보내고(`flush`), 지금 카메라의 렌더 패스·투영(`get_active_render_pass`·`get_projection_matrix`)
  으로 우리 파이프라인 셋(바닥 그림자 · 바람 · 법선)을 그린다. 셰이더는 원래 재질과 **같은 원본**(`WIND_VS`·`SHADOW_VERTEX`·
  `FLOOR_FRAGMENT`·`NORMAL_VS`)을 모듈 상수로 올려 함께 쓴다 — 한쪽만 고치는 일이 없게.
- 가리면 옅어지는 덩어리(덩어리마다 투명도)는 지금처럼 배치로 간다(15%).
- 지형이 다시 구워지면(열쇠가 바뀌면) 옛 버퍼를 지우고 새로 올린다 — GPU 메모리가 자라지 않게(0020, KB `gpu-memory-growth`).
- GL이 아닌 백엔드(iOS Metal)는 파이프라인을 만들지 않고 옛 길로.
- 랩 스위치 `render.resident`(기본 1, 0 = 옛 길) — 같은 판에서 A/B. 개발 창 도구 탭에 **"성능 줄 켬/끔"**(F3과 같은 개발 줄)을
  더해 키보드 없는 Android에서도 fps·cpu·프레임 시간·정점 수(+ 상주 정점)를 본다.

## 잰 결과(헤드리스 Chromium — GPU를 CPU로 흉내 내는 SwiftShader라 기기 숫자가 아니다)
| | 옛 길(0) | 상주(1) |
|---|---|---|
| 프레임마다 올리는 정점(개발 줄) | 약 351,600 | 약 104,300 (+ 상주 약 247,000은 한 번만) |
| 우리 코드 CPU 시간(평균) | 30~35ms | 13~16ms |
| 프레임 시간(rAF 240프레임 평균, 다른 짐 없을 때) | 128ms | 115ms |
- 그림은 같다(바닥·풀 흔들림·캐릭터 그림자·외곽선·빛줄기 — 같은 장면 스크린숏 견줌).
- `leak.js` 70초: 버퍼 164개·37.7MB에서 평평(자라지 않음).
- 첫 그림까지(로딩 덮개 걷힘) 두 빌드 모두 2.3~2.9초.
- 터치 시험의 세로 단계에서 4초에 덮개가 남은 것은 뒤에서 돌던 게임 페이지와 CPU를 나눈 탓(앞 페이지를 닫으면 4초에 게임) — 상주
  길이 초당 프레임을 더 그려서 생긴 일이라 회귀가 아니다.

## 남은 것
- **기기에서 A/B**(체크리스트 41): Android 개발판에서 정원 → 개발 창 "성능 줄 켬" → 연구소 `render.resident` 0 ↔ 1로 fps·frame을 견준다.
- 옅어지는 덩어리 581개도 상주로 옮기려면 덩어리마다 투명도 유니폼이 필요하다(그리기 호출이 수백 — 기기 결과를 보고).
- 뿌리 굴 전환(`render/descent.rs`)도 같은 꼴로 옮길 수 있다(전환마다 한 번 짓는 면).
