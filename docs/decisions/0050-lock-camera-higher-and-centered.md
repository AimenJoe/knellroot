# 0050. 락온 카메라를 높이고 방랑자를 가운데 가까이

- 날짜: 2026-11-04
- 상태: 채택·구현(사장: "숄더뷰에서 너무 캐릭터가 왼쪽으로 치우쳐 있어. 그리고 조금 높은 각도여야 적과의 거리재기 좋을 것 같아")
- 0040을 고친다: 그때는 큰 두건이 과녁을 가려 어깨를 1.6m 비켰다. 카메라를 높이면 방랑자가 화면 아래로 내려가 과녁을 덜 가리므로, 옆으로 비킬 필요가 줄어든다.

## 비교
같은 장면 셋(보스 결투 락온, 보스 아레나, 기둥 사이 락온)을 세 벌로 찍었다. 수치는 계산과 시험에서 나온 것이다.

| 벌 | 어깨 / 주시점 밀기 / 높이 | 내려다보는 각 | 방랑자 가로 자리(화면 반폭 대비) |
|---|---|---|---|
| 지금(0040) | 1.6 / 2.3 / 3.0 | 11° | −0.30 |
| B | 0.9 / 1.2 / 4.0 | 16° | −0.15 |
| **C(채택)** | **0.8 / 1.0 / 4.5** | **19°** | **−0.12** |

- C에서는 바닥 예고(원·부채꼴)와 둘 사이 바닥이 넓게 보여 거리를 재기 좋다. 방랑자가 보스 아래쪽에 서서 몸통·핵을 덜 가린다. B는 아레나에서 방랑자가 보스 다리를 덮었다.

## 시험 기준
- `lock_on_frames_the_player_left_of_center…`: "왼쪽 −0.15 넘게"를 **"조금 왼쪽(−0.2 ~ −0.05)"**으로 바꿨다.
- `lock_switch_is_smooth_from_every_side_of_the_target`(0009·0040):
  - 최악 회전 빠르기는 258 → 237°/s로 줄었다.
  - 그런데 가장 순한 쪽이 124 → 98°/s로 더 순해져, 최악/최선 배수만 2.1 → 2.4가 됐다.
  - 그래서 배수 기준을 2.5로 하고, **최악 260°/s**(0040 때 값) 기준을 더했다. 절대 한계 340°/s와 머리에서 4m 거리 기준은 그대로다.
- 얼린 값(0013): `CAM_L_SHOULDER` 0.8, `CAM_L_FRAME` 1.0, `CAM_L_HEIGHT` 4.5.
