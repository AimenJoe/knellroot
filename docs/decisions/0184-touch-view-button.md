# 0184 — 터치의 시점 버튼(쿼터뷰 ↔ 자유 숄더뷰)

- 날짜: 2026-11-14
- 상태: 채택·구현(판정 전 — 체크리스트 39)
- 사장: "터치스크린에서도 뷰를 바꿀 수 있는 방법이 있어야겠는데?"

## 왜
0181에서 터치는 **두 손가락 벌리기**(거리 단계 → 가장 가까운 단계에서 더 벌리면 숄더뷰)와 **숄더뷰에서의 오른쪽 반 끌기**만 받았다.
둘 다 화면에 보이지 않는 길이라 모르면 못 쓰고, 왼손 엄지가 스틱에 있는 동안 두 손가락 꼬집기는 손을 떼야 한다. 패드(십자 ↑↓)·
키보드(↑↓·휠)는 버튼이 있는데 터치에만 보이는 길이 없었다.

## 정한 것
1. **시점 버튼 `touch::Kind::View`**(눈 그림, 13×13 도트 — 다른 그림과 12칸 이상 다르다는 시험): 오른쪽 위 땅 돌리기 둘의 왼쪽에
   한 칸 띄워 같은 크기로(늘 있는 버튼 — 상황 버튼이 아니라 자리가 밀리지 않는다). 엄지 호 밖: 자주 누르지 않는 것.
2. **누르면 쿼터뷰 ↔ 자유 숄더뷰**(`Camera::toggle_view`): 거리 단계는 그대로 두어, 먼 쿼터뷰에서 숄더뷰로 갔다 오면 다시 먼
   쿼터뷰(시험). 락온 중에는 아무 일도 없다(카메라는 대상이 정한다). 입력은 `Actions::view`(틱마다 소비) — 패드·키보드는 지금처럼 거리 단계로.
3. 두 손가락 벌리기(거리 단계)·숄더뷰의 끌기(시점 돌리기)는 그대로 — 버튼은 보이는 길 하나를 더한 것.
4. **오른쪽 위 목표 줄**은 터치일 때 버튼 줄 밑으로 내린다(`touch::top_right_drop`) — 땅 돌리기 버튼부터 이미 목표 글과 겹치고 있었다.

## 확인
- 시험: `the_view_button_flips_between_quarter_and_shoulder_and_keeps_the_distance`, 터치 그림 시험(눈이 다른 그림과 갈린다), 늘 있는
  버튼 수(10).
- 헤드리스 `tools/test/touch.js`: 첫 화면에서 눈 버튼 = 숄더뷰 → 오른쪽 반 끌기 = 시점이 돈다 → 눈 버튼 = 쿼터뷰(스크린숏 t01b~d),
  목표 줄이 버튼 밑. 처음엔 이 단계를 싸움 중에 넣었더니 3초 사이 맞아 쓰러져 뒤 단계가 깨졌다 — 적이 먼 첫 화면으로 옮겼다.
- 못 한 것: 실제 폰에서 엄지가 닿는지·잘못 누르는지(사람 판정).
