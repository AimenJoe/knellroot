# 0187 — 돌린 뒤 캔버스 크기 다시 맞추기(웹)

- 날짜: 2026-11-14
- 상태: 채택(개발판 — 실기 판정 전, 체크리스트 42)
- 사장: "로딩 후 landscape로 화면 돌릴 때 가끔 화면이 꽉 차지 않고 일그러지는 경우가 있어"

## 원인
- 번들(miniquad 0.4.11 `js/gl.js` `resize`)은 `window.onresize` 때 **한 번만** 캔버스의 CSS 크기(`clientWidth`·`clientHeight` × dpr)를 읽어
  그리기 크기(`canvas.width`·`height`)를 정하고 게임에 알린다. 그 뒤로는 다시 보지 않는다.
- 폰 브라우저는 회전·전체 화면 때 resize를 레이아웃이 끝나기 전에 보내기도 한다(iOS Safari·Android Firefox의 버그 보고, 개발자 글 —
  2차 출처). 그때 읽은 크기는 옛 방향의 것 → 그리기 크기가 세로(1170×2532)로 박힌 채 가로 상자(2532×1170)에 늘어나 "꽉 차지 않고 일그러진다".
  "가끔"인 까닭 = 이벤트와 레이아웃의 순서가 그때그때 다르다.

## 정한 것
- 번들은 고치지 않는다(복사본은 의도적으로만 올린다). `web/index.html`에 작은 감시를 둔다: resize·orientationchange·fullscreenchange·
  visualViewport resize 뒤 50·150·350·700·1200ms와 다음 프레임에, 그리고 `ResizeObserver`(레이아웃이 끝난 크기를 준다)로 캔버스를
  다시 재서 **그리기 크기 ≠ 상자 크기 × dpr**이면 번들의 처리기(`window.onresize`)를 다시 부른다. 맞으면 아무것도 하지 않는다.
- 시험: `tools/test/touch.js` 세로 단계 끝 — 번들 처리기를 잠시 떼고(이벤트를 놓친 것과 같다) 가로로 돌린 뒤 되돌리면, 1.5초 안에
  그리기 크기가 상자와 같아야 한다. 고치기 전 빌드에서는 실패(1170,2532 ≠ 2532,1170), 고친 뒤 통과 + 화면이 꽉 찬다(`t15`).

## 남은 것
- 실기(Android Chrome·iPhone Safari)에서 여러 번 돌려 보기(체크리스트 42). APK(네이티브)는 처음부터 가로 고정이라 이 길과 무관.
- 첫 게임(nail)의 웹 빌드도 같은 번들 + 같은 꼴이면 같은 증상이 있을 수 있다 — 거기서 보이면 같은 감시를 옮긴다.
