# 0059. 넘치는 목록은 굴린다 — 모든 메뉴의 기본(`ui::ListView`)

- 날짜: 2026-11-05
- 상태: 채택·구현. 사장: "우리 ui 에는 화면 스크롤 기능이 기본적으로 있어야 할듯. 한화면에 모든 ui 가 들어갈수는 없으니."
- 근거: 첫 게임 nail 0199(끌어 굴리기·`ui::ListView`, 탭은 뗄 때), KB `reference/macroquad/gamepad-and-android-input.md`(끌기 함정)·`concepts/controller-layout-and-remapping.md`.
  가장자리 한 줄 여유는 게임 UI 관례(Roblox 개발자 포럼의 패드 스크롤 글·튜토리얼 — 2차, 공식 지침은 못 찾음).

## 무엇이 문제였나
- 메뉴는 줄을 정해진 간격으로 다 그렸다. 0058에서 설정이 여덟 줄이 되자 아래 안내와 겹쳤고, 그때는 간격을 줄여(`menu_in`) 넣었다. 조작 설정도 동작이 늘 때마다 간격을 줄여 왔다(0031). 줄이 더 늘면 줄일 곳이 없다.

## 결정
- **모든 메뉴는 넘치면 굴린다.** `Ui::menu(items, cursor, &mut ListView, cx, top, bottom)`: 줄 간격을 조금 줄이고(1.9 → 1.6줄), 그래도 `top..bottom`을 넘치면 보이는 줄만 그리고 위·아래에 더 있으면 ▲▼(누를 수 있다). 짧은 메뉴는 전과 같은 자리(타이틀 탭 자리를 쓰는 `touch.js` 그대로).
- **창은 `ui::ListView` 하나**(nail 0199를 가져옴): 보이는 첫 줄을 기억한다.
  - 키·패드 커서 → 창이 따라간다(`window`). 커서는 창 가장자리에서 한 줄 띄운다(목록 끝이 아니면) — 다음 줄이 보여야 더 있는 줄 안다.
  - 손가락 끌기·마우스 휠·▲▼ 탭 → 창을 직접 옮기고 커서를 창 안(여유 포함)으로(`scroll`). 줄 하나가 안 된 끌기는 쌓고, 방향을 바꾸면 버린다.
- **입력**: 메뉴 모드에서 손가락이 탭 범위(24px)를 넘게 움직이면 끌기(`Actions::drag`, 위로 끌면 + — 아래 줄이 드러난다). 끈 손가락은 뗄 때 탭이 아니다(0042·nail 0199: 탭은 뗄 때). 마우스 휠은 부호만 한 칸(`Actions::wheel`).
- **쓰는 곳**: 타이틀·멈춤·설정·결과·DEV(`menu`), 조작 설정 표(같은 `ListView`로 줄만 그리고 ▲▼). 앱은 화면마다 `ListView` 하나(장면이 바뀌면 처음부터).
- 새 목록 화면 = `ui.menu`에 위·아래 끝만 주면 굴린다. 줄 수를 세어 간격을 맞추는 코드를 화면마다 짜지 않는다.

## 확인
- 시험: `list_view_scrolls_by_drag_and_keeps_a_row_of_margin`(쌓이는 끌기, 끝에서 멈춤, 커서가 여유를 두고 창 안으로, 키 커서는 한 줄 앞서 굴림, 다 들어가면 0).
- 지금 메뉴는 UI가 화면 높이에 비례해(0041·0046) 어느 해상도에서도 넘치지 않는다 — 굴리기는 줄이 늘 때 켜진다. 그래서 설정 목록을 화면 아래로 내린 임시 빌드로 헤드리스 확인(커밋 안 함): 키로 내려가면 창이 따라가고 ▲▼, 휠 위로 세 칸, 폰 크기(844×390, 터치)에서 손가락으로 위로 끌면 끝까지 굴러가고 줄은 눌리지 않는다. 실제 빌드로 `mouse.js`·`shot.js`·`touch.js` 다시 통과.

## 사람이 볼 것
- 지금은 넘치는 메뉴가 없어 눈에 띄지 않는다. 줄이 늘어 굴리기가 켜지면: 끄는 빠르기(1:1), 탭 범위 24px가 알맞은지(끌려다 줄이 눌리지 않는지).
