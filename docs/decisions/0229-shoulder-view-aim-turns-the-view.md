# 0229 — 숄더뷰의 조준 = 화면을 돌린다(터치 끌기도)

- 날짜: 2026-11-18
- 상태: **결정 + 만듦**(개발판 `release/v0.7`, 실제 폰 판정 전) — **0230이 좁힘**: 끌면 시점이 도는 것은 한 대상을 겨누는 버튼만, 범위는 바닥 표시
- 사장: "공격방식이 조준인 경우, 쿼터뷰에서는 단순히 2d 방향만 맞추면 되지만, 숄더뷰에서는 조준하고 있으면 화면이 회전되어야 하지
  않아? 크로스헤어로 조준하는 의미가 그거잖아?"
- 바탕: 0181·0188(자유 숄더뷰 — 오른쪽 스틱·마우스·화면 오른쪽 반 끌기 = 시점), 0217(터치 끌어 조준), 0219(숄더뷰 원거리 = 카메라
  앞, "끄는 손가락은 시점이 아니라 조준"), 0222(크로스헤어), 0227(`aim_sight`), 0228(보정은 닿는 적에만).

## 왜
- 뒤에서 보는 3인칭의 크로스헤어는 "화면 가운데가 겨눈 곳"이다. 그러니 겨누는 일 = 시점을 돌리는 일. 쿼터뷰의 "땅 위 2D 쪽"과 다르다.
- 패드(오른쪽 스틱)·마우스(잡힌 커서)·키보드(←→)는 숄더뷰에서 이미 시점을 돌리고, 원거리는 크로스헤어로 나간다 — 맞게 돼 있었다.
- **터치만 어긋났다**: 0219가 "숄더뷰에서도 겨누는 버튼을 끌면 시점이 아니라 쪽"으로 정했다. 그래서 숄더뷰에서 버튼을 끌면 화면은 그대로인데
  탄이 크로스헤어가 아닌 끈 쪽으로 나갔고, 땅 위에 띠까지 그려졌다(0222 "숄더뷰는 바닥에 그리지 않는다"와도 어긋남). 크로스헤어가 거짓이 됐다.
- 모바일 TPS의 관례: 쏘기 버튼을 쥔 채 끌면 시점이 돈다(PUBG Mobile — 오른쪽 쏘기 버튼은 끌어 시점을 옮긴다, 2차 출처: 공략 글).

## 결정
1. **숄더뷰(`Mode::Free`)에서 겨누는 버튼(원거리 둘·쪽이 있는 스킬 칸)을 끌면 끈 만큼 시점이 돈다**(`touch::Ctx::look_aim` — 앱이 매 프레임,
   손가락의 프레임 사이 이동을 `Actions::look`에 — 화면 오른쪽 반 끌기와 같은 셈·같은 민감도).
2. **떼면 그 일이 크로스헤어로**: 원거리는 월드가 이미 크로스헤어의 적(`aim_sight`)·카메라 앞(`aim_ahead`)으로 겨눈다 — 누름만 보낸다.
   쪽이 있는 스킬은 카메라 앞으로 못 박는다(`touch::free_aim_end` → `aim` = 위 + `aim_drag`). 쥔 채 오래면 모으는 것은 그대로(0217).
3. **숄더뷰에는 취소 자리가 없다**: 손가락 자리가 쪽을 말하지 않으니 "가운데로 돌아와 떼면 취소"가 뜻이 없다(우연히 취소된다). 땅 위 미리보기도
   그리지 않는다(크로스헤어가 표시) — 버튼 둘레 고리·손잡이는 남긴다(쥐고 있다는 표시).
4. **락온 중·쿼터뷰는 그대로**(0217 — 끈 쪽 = 2D 쪽, 톡 = 가까운 적, 취소).

## 그대로 둔 것(판정 거리)
- 패드·키보드로 숄더뷰에서 쓰는 쪽이 있는 스킬(가로지르기·제비걸음·던지기 등)은 0151대로 걷는 쪽 > 조준 > 락온 > 바라보는 쪽 —
  크로스헤어로 가지 않는다. 원거리 탄만 크로스헤어. 스킬도 크로스헤어로 보낼지는 판정 뒤에.
- 숄더뷰에서 조준할 때 카메라를 어깨로 당기는 확대(ADS)는 없다.

## 시험
- `in_the_shoulder_view_a_dragged_button_fires_where_the_crosshair_is`(뗄 때 누름·스킬만 카메라 앞·모으던 탄은 누름 없이).
- 헤드리스 `touch.js` `t01c2-shoulder-aim-drag`(숄더뷰에서 특수 버튼을 끄는 중 — 화면이 돌고 땅에 띠가 없다).
