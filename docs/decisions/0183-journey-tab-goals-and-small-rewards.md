# 0183 — 여정 탭: 지역마다의 목표 + 받기로 작은 보상

- 날짜: 2026-11-14
- 상태: 채택·구현(판정 전 — 체크리스트 38)
- 사장: "좋은 건 넣어야지, 이걸 넣는다고 불편해지는 것도 위험을 무릅쓰는 것도 아니니까"(PR 21 리뷰에서 퀘스트 체계를 "새 기능 — 결정 필요"로
  적은 데 대한 답). 인터뷰 셋: 발견 보상 = **작은 보상, 받기로** · 보는 곳 = **큰 창의 새 탭** · 범위 = **지금 두 지역 + 체계**.

## 왜(스터디)
- 소울라이크는 퀘스트 창 없이도 굴러간다(다크 소울·할로우 나이트·엘든 링) — 하지만 엘든 링은 놓친 NPC 이야기가 많아 패치로 지도 표시를
  더했다(Game Developer·PC Gamer 비평, 2차). 퀘스트의 일은 둘 — **어디로**와 **왜**. 우리는 "어디로"를 이미 목표 글 한 줄·빛기둥·화살·
  종소리(0060·0170·0171)로 하고 있었고, 빠진 것은 **놓치기 쉬운 것을 모아 보는 곳**이었다.
- 꼴은 nail 저널(KB `roguelite-journal-goals`, nail 0048) — 표 하나 + 진행은 기록에서 다시 센다 + "받았다"만 적는다 + 받기는 메뉴에서.

## 정한 것
1. **`journey.rs` 표 `GOALS`**(지역 · 갈래 · 이름 · 풀이 · 세는 것 · 보상). 갈래 둘:
   - **갈 길**(주요): 화면 목표 글과 같은 일 — 성소 문을 열어라 · 성소의 문지기를 넘어라 · 종탑 터의 종지기를 넘어라.
   - **발견**: 놓쳐도 길이 막히지 않는 것 — 성소의 종소리 조각 모두 · 성소의 강한 개체 모두 · 다시 일어서는 문지기를 보아라 ·
     마을의 새긴 돌 모두 읽기 · 먹고 있는 잔재를 지켜보아라 · 마을의 강한 개체 모두 · 마을의 숫돌 모두.
2. **진행은 이미 있는 기록에서 센다**: 문(`gates`)·핵(`core.*`)·숨은 물건(`finds` — 지도 글자 수가 목표)·엘리트(`elites`)·도감 관찰
   (`codex` — `warden.roused`·`husk.docile`). 새로 적는 것은 둘뿐 — **읽은 새긴 돌**(`read`, `<지역>.<몇째>`)과 **받은 목표**(`journey`).
   목표를 더하거나 수를 바꿔도 쌓인 기록으로 바로 맞춰진다.
3. **보상은 작게, 받기로**: 잔불 20~70(한 단 값 50 + 25 안 — 시험), 기술 점수는 지역마다 하나까지(성소 = 종소리 조각 모두, 마을 =
   새긴 돌 모두 — 시험). 새 화폐는 없다(lore growth). 기술 점수는 따로 적지 않고 `Progress::skill_points`가 받은 목표에서 센다.
   받기는 멈춤에서도 된다(사는 일이 아니다) — 탭 머리의 민트 점도 멈춤에서 뜬다(다른 탭의 점은 화로에서만, 0164 그대로).
4. **보이는 것**: 첫 지역은 늘, 마을은 성소의 문지기를 넘은 뒤(내려가는 길이 그때 열린다). 줄 끝 표지: ◆ 받을 수 있다 · n/m 하는 중 ·
   ◇ 받았다(흐리게). 오른쪽 = 이름 · 갈래와 지역 · 상태 · 풀이 · 받을 것.
5. **알림**: 새로 이룬 목표는 "여정 — 이름" 한 줄(다른 알림이 떠 있으면 비켜 탭 머리 점만). 기록을 처음 본 때(불러오기)는 이미 이룬 것을
   조용히 적어 둔다 — 이어할 때마다 지난 일을 다시 알리지 않게.
6. **넣지 않은 것**: 주민(lore — 주민은 보상·진행의 수단이 아니다), 핵의 반응·종소리의 근원을 드러내는 이름(README 단서 규칙 "이름표·목표
   글이 가장 세게 드러낸다" — PR 21 리뷰 A-8), 관찰 판정을 위한 새 장치(이미 있는 도감 관찰만 쓴다).
7. **탭 차례**: 상태 · 장비 · 기술 · 도감 · **여정** · (가게) · 설정 — 헤드리스 `shot.js`·`hearth.js`의 탭 길을 고쳤다.
