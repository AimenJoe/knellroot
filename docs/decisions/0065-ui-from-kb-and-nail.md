# 0065. UI 기본틀은 KB와 nail에서, 없는 꼴은 스터디 먼저

- 날짜: 2026-11-05
- 상태: 채택(사장: "UI 기본틀은 KB 및 under the roots 참조해보고, 없는 형태의 새로운 UI 가 필요한 경우 스터디 후 진행하도록 해.")
- 지금(2026-11-05 결정 검토, 0066 때): "아직 다른 것" 두 줄(슬롯 하나·가운데 목록)은 0066이 걷었다(슬롯 셋·nail 창 틀).
- 계기: v0.3.0(0064)의 새 화면(이어하기·새로 하기, 장비 창, 화로 가게, 핵 고르기, 알림)을 만들 때 KB의 UI 노트와 nail의 같은 화면을 먼저 읽지 않았다. 다시 대어 보니 어긋난 곳이 다섯.

## 규칙
- 새 화면·메뉴·알림을 만들기 전에 **KB**(`maps/gamedev.md` → UI 노트: `controller-layout-and-remapping`(굴리는 목록·묻는 창)·`hud-readability-and-quick-slots`·`roguelite-save-slots-and-continue`·`meta-progression-unlock-planning`·`game-audio-without-a-composer`(메뉴 소리))와 **nail의 같은 화면**(`app/`의 가게·멈춤 탭·슬롯·나무)을 읽고, 같은 꼴로 만든다. 다르게 할 때는 까닭을 결정 기록에 적는다(예: knellroot에는 nail의 창 틀(패널)이 없어 가운데 목록으로).
- KB에도 nail에도 없는 꼴이면 **먼저 스터디**(다른 게임·지침 1차 자료) → 제안 → 사장 확인 뒤 만든다. 배운 것은 KB에.

## 아직 다른 것(까닭)
- 저장 슬롯은 하나(KB·nail은 셋 + 슬롯 고르기): items.md 6 "처음엔 하나". 슬롯이 필요해지면 KB 노트의 꼴(시작하기/이어하기 → 슬롯 고르기, 설정은 슬롯 밖)로.
- 가게·장비는 nail의 창 틀(패널·초상화) 대신 knellroot의 가운데 목록(0042·0059) — 묻는 창은 가게 목록을 깔지 않는다(목록 위에 글이 겹쳐 읽기 어려웠다, 스크린숏).

## 확인
- 시험: `flow` 묻는 창(멈춤 → 묻는 창, 답 → 장면·다시 세우기, 취소 = 온 곳, 커서 처음 자리). 헤드리스 `save.js`: 사기 묻는 창 → 사기, 처음부터·타이틀로 묻는 창(취소에서 시작 — 위로 한 번), 새로 하기는 취소하면 그대로·"기록 지우기"를 골라야 지워짐. `shot.js`의 타이틀로 길도 묻는 창을 지나게. `docs/art/v030/asks.png`.
