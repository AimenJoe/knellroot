# 0061. 그림 기준 = t3ssel8r 풍 3D 도트 — 모델링할 때 늘

- 날짜: 2026-11-05
- 상태: **상설 규칙**(사장: "늘 모델링 할때는 t3ssel8r 의 스타일을 생각해, 예쁘니까!"). 0037(색 = 생명)·0033(툰·외곽선)과 함께 간다.
- 근거: KB `concepts/3d-pixel-art-look.md`(이번에 씀). **t3ssel8r 본인의 영상·글은 아직 직접 보지 못했다** — 재구현기(David Holland 글, Otavio Peixoto 글, Godot 포럼)와 논문 한 편의 설명이다.

## t3ssel8r 풍이란(2차 출처로 모은 것)
- 3D를 **낮은 해상도로 그려 정수배로 키운다**(가장 가까운 픽셀).
- **툰 빛**: 빛을 몇 단으로 끊는다.
- **선 둘**: 깊이가 끊기는 곳(물체 가장자리)은 어두운 1px 선, **볼록한 모서리는 밝은 선**(법선이 꺾이는 곳). 밝은 선이 이 룩의 표지다.
- **카메라를 화면 픽셀 격자에 맞추고 남은 소수점은 화면에서 민다** — 걸을 때 픽셀이 기어가지 않는다. 직교 카메라에서만 깔끔하다.
- 바닥은 **풀·잎 빌보드**(바닥과 같은 툰 빛)와 높낮이로 살린다. 물·구름 그림자·빛줄기 같은 효과가 더해진다.

## 모델링할 때(체크리스트 — 위 출처를 이 게임에 옮긴 Claude의 정리)
1. **면이 또렷한 로우폴리, 면마다 평평한 법선** — 툰 띠와 모서리 선이 면에서 나온다. 매끈한 고폴리는 띠가 얼룩진다. Meshy 결과는 줄이고 평평하게(0038 파이프라인 + 면 법선).
2. **실루엣 + 큰 색 덩어리**(2~4색, 명도 단계). 잔무늬 텍스처보다 형태로 말한다. 색은 0037 팔레트에서.
3. **볼록 모서리를 일부러 둔다** — 밝은 선이 붙을 자리(갑옷 테·돌 모서리·뿔·핵의 각).
4. **게임 거리에서의 크기를 먼저 잰다** — 쿼터뷰에서 몇 px 높이인지 보고, 그보다 작은 디테일은 빼거나 색 한 칸으로.
5. 텍스처를 쓰면 **텍셀 ≈ 게임 거리의 화면 1px**, 가장 가까운 픽셀.
6. 판정은 늘 **게임 안 스크린숏**(쿼터뷰·락온)으로 — 미리보기 렌더가 아니라.

## 0060 고칠 일에 주는 뜻
- **W2 바닥**: 0060의 "작은 텍스처 먼저"를 고친다 → 높낮이·석판 모서리(밝은 선이 붙게) + 풀 빌보드 + 팔레트가 먼저, 텍스처는 보조.
- **W3 적**: 그림 프롬프트에 "로우폴리·면이 또렷한·큰 색 덩어리"를 넣고, Meshy 결과는 줄여 면 법선으로.
- **렌더 쪽 빈칸**(사장이 정할 것): ① 볼록 모서리 밝은 선 + 모든 것에 어두운 선(화면 공간 가장자리 검출 — 법선·깊이 텍스처가 필요해 macroquad에선 따로 패스) ② 카메라 픽셀 흔들림(원근이라 쿼터뷰만 직교로 바꾸거나 시야를 좁혀 줄이는 식 — 0003의 두 리그 원근·전환 보간과 부딪힌다).
