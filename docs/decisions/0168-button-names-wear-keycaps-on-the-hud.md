# 0168. 싸움 화면의 버튼 이름도 키캡으로 — 더 또렷한 키캡

- 날짜: 2026-11-13
- 상태: **결정**(사장 2026-11-13, 0167의 힌트를 보고 — "키나 버튼에 대한 표시는 더 눈에 띄어야지, 버튼처럼") — 만듦, 판정 전(체크리스트 25-11).
- 바탕: 0042(키 이름은 키캡 `ui::key` — 메뉴의 안내 줄), nail 0153(키캡), KB `concepts/hud-readability-and-quick-slots.md`.
- 그림: `docs/art/gui-0168/`(01 힌트 + 곁의 할 일 + 스킬 칸 · 02 가로 폰 · 03 큰 창의 안내 줄).

## 왜
0167의 힌트는 버튼 이름을 글과 같은 빛의 낱말로 썼다("[4/8] SHIFT 패링"). 곁의 할 일("F 쉬기")과 스킬 칸 밑의 "Q"·"E"도 그랬다. 글 속의 낱글자는 버튼으로 읽히지 않는다 — 무엇을 누르라는 것인지가 힌트의 전부인데 그것이 가장 덜 보였다. 메뉴의 안내 줄은 처음부터 키캡이었다(0042) — 싸움 화면만 빠져 있었다.

## 정한 것
- **싸움 화면에서 버튼 이름을 쓰는 세 자리를 모두 키캡으로**: 튜토리얼의 힌트(머리 줄 속), 곁의 할 일("키 + 쉬기·줍기 …" — 할 일은 전처럼 호박색), 스킬 칸 밑의 이름.
- **키캡 자체를 더 또렷하게**(메뉴의 안내 줄도 같이 바뀐다 — 한 부품이다): 테를 밝게(어두운 갈색 → 밝은 호박빛), 아랫변을 두 배로 두껍게(눌리는 키의 턱). 칸의 크기·자리는 그대로(넘침 검사가 보는 칸이 같다).
- 터치는 전처럼 이름이 없다(화면 버튼이 곧 안내).

## 코드
`ui.rs` `KEY_EDGE`·`KEY_LIP`(턱), `hud.rs` `key_line`(키캡 + 할 일 한 줄 — 할 일의 빛을 지킨다: 키캡이 든 글은 어두운 빛을 본문 빛으로 바꾸므로 둘로 나눠 그린다)·`draw_skills`, `app/play.rs` `tutor_hint`(버튼 이름을 `ui::key`로 감싸 넘긴다 — `tutorial.rs`는 표시를 모른다).

## 시험 스크립트에서 찾은 것
`tutorial.js`·`hearth.js`가 기록을 심을 때(게임이 도는 쪽에서 `localStorage`에 쓰고 → 다시 띄우기) 그 사이에 게임이 제 기록을 덮어쓰는 경합이 있었다 — 걸음이 바뀔 때 기록을 쓰는 튜토리얼이 생기며 드러났다(여덟째 걸음의 그림에 일곱째가 찍혔다). 같은 출처의 빈 쪽으로 나가서 심고 돌아오게 고쳤다.

## 확인
시험 507 + 무시 2, clippy 다섯, CI가 도는 넷, `hearth.js`·`tutorial.js`(한국어·영어 넘침 0). 화면으로 봄(큰 화면·가로 폰). 패드의 이름(X·B·LT …)이 든 키캡은 헤드리스로 못 봤다.
