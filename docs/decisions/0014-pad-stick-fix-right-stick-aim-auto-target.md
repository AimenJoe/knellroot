# 0014. 패드 왼쪽 스틱 위아래 고침 + 오른쪽 스틱 조준 + 공격 자동 조준

- 날짜: 2026-11-03
- 상태: 채택·구현(사장: "안드로이드 게이밍 핸드헬드에서 왼쪽 스틱으로 조종하니 이상한 방향으로 이동함, D패드는 제대로. 오른쪽 스틱으로 캐릭터가 바라보는 방향을 조절할 수 있어야 할 듯, 다만 공격할 때는 가장 가까운 적 오토 타겟(특정 거리 이하일 경우)").

## 왼쪽 스틱이 엉뚱한 쪽으로 간 까닭
- 웹 패드 플러그인(`web/macroquad-gamepads-0.1.js`)이 축 1·3(세로)을 이미 뒤집어 넘기고, `gamepads` 크레이트 문서도 "negative values representing down" — 즉 **위 = +**로 온다.
- 우리 코드가 `vec2(lx, -ly)`로 한 번 더 뒤집었다. 첫 게임(nail)은 이동 축이 "화면 아래 = +"라 그 줄이 맞았고, Knellroot는 "앞 = +"인데 그 줄을 그대로 가져왔다 → 좌우는 맞고 위아래만 반대 → 대각선이 엉뚱하게. D패드는 우리 코드가 직접 `y += 1`로 읽어 멀쩡했다.
- 고침: `input::stick`(그대로 넘김) 한 곳 + 시험 `pushing_a_stick_up_means_forward`. 배운 것: 축 규약이 다른 프로젝트에서 입력 줄을 가져올 때는 부호를 시험으로 박는다.
- 덧붙여 확인: 이 컨테이너에는 `aarch64-linux-android` 대상이 없어 `cargo check --target aarch64-linux-android`가 코드와 상관없이 실패한다(바꾸기 전 코드도 같음). APK 쪽 패드는 기술 검토대로 miniquad 패치가 아직 없다(웹판은 상관없음).

## 오른쪽 스틱 = 바라보는 쪽, 공격 = 가까운 적 자동 조준
- `Actions::aim`(오른쪽 스틱, 이동과 같은 기준으로 월드 방향). 쥐고 있으면 그쪽을 본다 — 걸으며 다른 쪽을 볼 수 있다. 락온 중엔 쓰지 않는다(대상을 본다).
- 휘두르는 순간 방향을 그 자리에서 정한다(돌아가는 시간 없이): **자동 조준 > 조준 스틱 > 지금 바라보는 쪽**.
  - 자동 조준: `aim.auto range m`(3.0, 적 몸 가장자리까지) 안의 가장 가까운 산 적.
  - 조준 스틱을 쥐고 있으면 그 쪽 `aim.auto cone deg`(90°, 전체 각) 안에서만 고른다 — 사장 말("가장 가까운 적")을 따르되, 일부러 먼 적을 겨눌 때 옆의 가까운 적이 가로채지 않게. 그 쪽에 적이 없으면 스틱 쪽 그대로.
- 터치·키보드는 조준 스틱이 없다 — 자동 조준만으로도 휘두르는 쪽이 맞는다.
- 시험: 가장 가까운 적으로 돈다 / 범위 밖이면 안 돈다 / 스틱 쪽 부채꼴 안에서 고른다 / 그 쪽에 없으면 스틱 쪽 / 오른쪽 스틱이 움직이지 않고 돌린다 / 걸으며 다른 쪽을 본다.
- 값은 새로 두 개(얼린 값 57+1개는 그대로, `docs/tuning-frozen.txt`에 두 줄 더함).

## 다시 볼 조건
- 자동 조준이 너무 친절해서 조준이 의미 없어지면(P3 판정): 범위를 줄이거나 "스틱을 쥐었을 때만 부채꼴 안" 규칙을 늘 켠다.
- 락온 중 오른쪽 스틱은 대상 바꾸기(소울류)로 쓸 수 있다 — P3에서.
