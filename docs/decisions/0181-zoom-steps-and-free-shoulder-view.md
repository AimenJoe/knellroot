# 0181. 시점 거리 단계 · 자유 숄더뷰 — 십자 ↑·↓로 당기고, 넘으면 숄더뷰, 잃은 락온은 숄더뷰에 머문다

- 날짜: 2026-11-14
- 상태: **결정**(사장 2026-11-14) — 만듦, 판정 전(체크리스트 36). 0011(쿼터뷰 방위)·0012(땅 돌리기)·0024(조작)·0058(마우스)·2026-11-06 "락온 대상이 쓰러지면 다음 적"을 잇는다.

## 사장의 말
- (물음 "락온 말고 시점을 바꿀 수 있는 방법, 어떤 키 조합으로?"에 대한 제안 — 십자 ↑·↓ = 거리 단계, 땅 돌리기는 그대로) 뒤:
  "그래 십자키 위로 줌, 아래로 줌아웃. 특정 거리 이상 줌 하면 숄더 뷰로 보이도록 하자. 그러면 이제 락온 했을 때 적이 죽거나 사라지면 그냥
  숄더뷰 유지해 주고, 오른쪽 스틱으로 시점 조절 가능하면 되겠다. 터치 스크린에서도 화면 중앙부를 드래그하면 시점 이동되도록(원신 식)."

## 정한 것
### 거리 단계와 자유 숄더뷰(`camera.rs`)
- 쿼터뷰 거리는 세 단계 `QUARTER_ZOOM` = `cam.quarter.dist` × 1.3 · 1.0(처음) · 0.75. 가장 가까운 단계에서 한 번 더 당기면 **자유 숄더뷰**(`Mode::Free`),
  자유 숄더뷰에서 밀면 쿼터뷰의 가장 가까운 단계로. 단계는 0.3초에 옮겨 간다. 연속 줌이 아니라 단계인 까닭: 거리는 멀미와 타격감의 맞바꿈이라
  (KB camera-mode-switch) 사람이 판정한 범위 안에서 고르게.
- 자유 숄더뷰 = 락온과 같은 어깨 리그(`Camera::shoulder` — 거리·높이·어깨·주시점·FOV는 `cam.lock.*` 그대로)를 대상 없이. 방위(요)와 높이 각은
  플레이어가 돌린다. 높이 각은 −0.25 ~ +0.65 라디안(땅 밑·머리 위로 넘어가지 않게).
- 쿼터뷰에서 들어가면 화면 위였던 쪽이 앞(스틱의 위가 같은 쪽 — 걷던 쪽이 꺾이지 않는다, 시험).
- 입력 기준(`World::view_yaw`)은 자유 숄더뷰에서 카메라가 보는 쪽(`Camera::basis_yaw_deg`) — 스틱 위 = 카메라 앞.
- 땅 돌리기(0012)는 자유 숄더뷰에서도 앞을 90° 돌린다(쏟기·휘청은 그대로).
- 락온 중에는 거리 단계를 받지 않는다(카메라는 대상이 정한다).
- 고른 거리 단계와 자유 숄더뷰는 새 카메라(쉼터·지역 전환·되살아남)로 이어 간다(`Camera::renew`). 기록에는 남기지 않는다(판을 다시 켜면 처음 단계).

### 락온이 풀릴 때
- **버튼으로 풀면** 락온한 곳으로: 쿼터뷰에서 락온했으면 쿼터뷰, 자유 숄더뷰에서 했으면 자유 숄더뷰(`Camera::unlock_mode`).
- **버튼 없이 풀리면**(대상이 쓰러지고 넘길 적이 없음 · 대상이 사라짐 · 너무 멀어짐) 월드가 `Event::LockLost`를 내고 카메라는 **숄더뷰에 머문다**
  (자유 숄더뷰 — 그 순간의 방위 그대로). 다음 적으로 넘기기(2026-11-06)는 그대로 먼저다.

### 시점 돌리기(자유 숄더뷰에서만)
| 장치 | 거리 단계(당기기 / 밀기) | 시점 돌리기 |
|---|---|---|
| 패드 | 십자 ↑ / ↓ | **오른쪽 스틱**(방위 초당 150° · 높이 80°, 끝까지 기울였을 때) — 자유 숄더뷰에서는 조준이 아니다 |
| 키보드+마우스 | ↑ / ↓ · 휠 위 / 아래 | **마우스 움직임**(커서를 잡는다 — 웹은 포인터 잠금, 0.2°/px). 메뉴·패드·터치로 바뀌면 놓는다 |
| 키보드만 | ↑ / ↓ | ←·→ (방위만) |
| 터치 | 화면 오른쪽 반의 빈 자리에 **두 손가락 벌리기 / 오므리기**(60px마다 한 칸) | 화면 오른쪽 반의 빈 자리를 **한 손가락으로 끌기**(원신 식, 0.3°/px) |
- 높이를 방위보다 느리게: 위아래 흔들림(수평축 회전)이 멀미를 더 부른다(KB camera-mode-switch의 2차 연구 요약).
- 위로 밀면 위를 본다(뒤집지 않음 — 스틱·마우스·끌기 같은 쪽).
- 자유 숄더뷰에서는 오른쪽 스틱·커서가 조준이 아니니 공격은 자동 조준(가까운 적)·바라보는 쪽으로 나간다. 락온은 그대로 R3·휠 클릭.
- 터치의 왼쪽 반은 이동 스틱 그대로, 버튼 위의 손가락은 버튼이 먼저.

### 화살표 키는 걷지 않는다
- 키보드의 화살표 ↑·↓는 거리 단계, ←·→는 자유 숄더뷰의 시점(패드의 십자 키와 같은 일). 걷기는 W·A·S·D만. 메뉴의 화살표는 그대로.
  (Android·iOS에서는 화살표 키코드가 곧 패드의 십자 키라 같은 뜻이다.)
- 조작 설정 화면의 고정 안내: "이동·확인·뒤로·멈춤·시점(↑↓ 거리)은 고정".

## 왜 이 꼴인가
- 오른쪽 스틱은 쿼터뷰에서 조준(0014)이다 — 숄더뷰에서만 시점으로 쓰면 둘이 겹치지 않는다(같은 스틱에 조준·회전·줌을 얹은 게임은 "돌리면 줌이 먹는다"는 불만, 포럼 2차).
- 패드의 빈 버튼은 십자 ↑·↓뿐이었다(LB = 패링, RB = 마법, ←·→ = 땅 돌리기).
- "숄더뷰 = 보스전"(concept)의 구도는 락온에 그대로 남고, 자유 숄더뷰는 그 구도를 탐험·떼싸움에서도 고를 수 있게 한다.

## 판정에서 볼 것(체크리스트 36)
- 거리 셋(1.3 · 1.0 · 0.75)과 숄더뷰로 넘어가는 자리가 맞나 · 숄더뷰에서 떼싸움이 되나(뒤가 안 보인다).
- 오른쪽 스틱·마우스·끌기의 빠르기(150°/s · 0.2°/px · 0.3°/px), 위아래 뒤집기 설정이 필요한가.
- 잃은 락온이 숄더뷰에 머무는 것 · 버튼으로 풀면 락온한 곳으로 돌아가는 것.
- 마우스의 커서 잡기(웹 포인터 잠금 — 브라우저가 처음 한 번 클릭을 요구할 수 있다) · 터치의 오른쪽 반 끌기가 버튼과 부딪히지 않나.
- **헤드리스로 못 본 것**: 실제 패드의 오른쪽 스틱·십자 키, 마우스 포인터 잠금, 터치 끌기·꼬집기(단위 시험만).
