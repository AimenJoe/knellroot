# 0028. 땅 돌리기 = 캐릭터 기준 90°(몸과 화면이 같이 90°) — 0023을 고침

- 날짜: 2026-11-03
- 상태: 채택·구현. 0023의 "오른쪽 면을 화면 위로 맞추기"를 대신한다.
- 사장: v0.1.1 뒤 "수정사항 제대로 반영된거 맞니? 화면 회전에 대해서, 대상이 되는 화면 축이 올바른지 다시 한번 확인해줘" → 16가지 탐침 결과를 보여 묻자 "캐릭터 기준으로 90도 도는거잖아".

## 무엇이 틀렸나(0023)
0023은 "누르기 전 캐릭터의 오른쪽 면이 새 정면"을 **"그 면이 화면 위가 되게"**로 읽었다. 화면 위는 넷뿐이라, 캐릭터가 바라보는 쪽에 따라 화면이 도는 각과 방향이 바뀌었다.
- 시뮬레이션 탐침(월드 + 카메라를 함께 돌림, 걷는 쪽 넷 × 버튼 둘 × 스틱 쥔 채·놓고 = 16, 쿼터뷰 요 35°):
  - 위로 걷다 오른쪽: 화면 오른쪽으로 90°. 여기만 사장의 그림과 맞았다.
  - 오른쪽으로 걷다 오른쪽: 화면 **180°**. 스틱을 쥔 채면 **왔던 길로 되돌아갔다**(쥔 → 새 화면 기준 오른쪽 = 옛 왼쪽).
  - 오른쪽으로 걷다 왼쪽: 화면은 **그대로**, 몸만 위로. 쥔 스틱이면 다시 오른쪽으로 걸었다.
  - 아래로 걷다 오른쪽: 화면(시점)이 **왼쪽으로** 90°.
- 대상 면은 맞게 골랐지만(16/16), "화면이 오른쪽으로 90°"와 "직진할 수 있는 상태"는 위로 걸을 때만 지켜졌다.

## 정한 것
- 오른쪽 버튼: 캐릭터가 **제 오른쪽으로 90°** 돌아서고(`facing - 90°`), 화면도 **늘 오른쪽으로 90°**(요 -90°, 화면 오른쪽에 있던 것이 위로). 왼쪽 버튼은 거울.
- 몸과 화면이 같은 회전이라 캐릭터가 화면에서 보는 쪽은 그대로다. 쥔 스틱은 바로 새 화면 기준(0023 그대로) — 그래서 어느 쪽으로 걷다 눌러도 쥔 채로 새 정면(누르기 전 오른쪽 면)으로 직진한다.
- `world::plan_turn(right, facing)` — 카메라 방위가 필요 없어졌다. 180°·몸만 돌기(`TURN_HALF_MUL`·`TURN_SPIN_ONLY`)는 이제 쓰이지 않는 칸 수지만 카메라 함수는 그대로 둔다(되돌릴 때를 위해).
- 시험: `a_turn_is_always_ninety_degrees_the_buttons_way_for_body_and_screen`, `after_a_turn_the_held_stick_walks_straight_to_the_new_front`(걷는 쪽 넷 × 버튼 둘). 탐침 16가지 다시: 몸 = 누르기 전 옆면, 화면 = 버튼 쪽 90°, 걷는 쪽 = 새 정면, 16/16.

## 다시 볼 조건
- 쿼터뷰 요(35°)가 지도 축과 어긋나 있어, 대각으로 걷다 돌리면 새 정면도 대각이다. 복도에서 어색하면 몸만 가까운 화면 축으로 맞추는 것을 본다(화면은 그대로 90°).
