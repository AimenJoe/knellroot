# 0068. 아이템의 모양을 실제로 보이기 — 아이콘 캐시 + 고른 것만 3D

- 날짜: 2026-11-05
- 상태: **채택·구현**(사장 2026-11-05 "응 추천대로 진행해줘. 근데 검은 실루엣 같은건 도감에서나 쓰이면 되는것이고 상태창에서는 보일필요가 없어..") — 정할 것 1·2는 추천대로, 3은 **장비 창에서 못 얻은 것을 아예 빼기**(실루엣은 도감 몫). 처음 물음: "아이템에 대한 정보를 볼때 아이템의 모양을 실제로 보여주고 싶은데 어떻게 해야할까?"
- 지금: 장비 창(0067 D)은 인형이 든 무기만 그림으로 보인다. 칸·후보 줄·설명은 글뿐. 장신구는 모델이 없다(`assets/models/`에 없음 — 무기 넷은 `wanderer.glb`의 오른손 부위 `sword`·`w_hammer`·`w_staff`·`w_crossbow`).

## 스터디
- KB `readable-low-poly-models`: 작은 크기에서 읽히는 것은 디테일이 아니라 **실루엣과 명도**. KB `hud-readability-and-quick-slots`: 칸 아이콘은 크게, 고른 칸은 두꺼운 금빛 테두리, 못 쓰는 것은 흐리게.
- nail: 장비 그림은 코드로 그린 2D 아이콘(`draw_weapon_icon`·`draw_charm_icon`, 칸 격자) — 2D 도트 게임이라 맞았다. 우리는 3D라 같은 모델로 그리는 편이 화풍이 맞는다(0061 "판정은 게임 안 스크린숏").
- 바깥(포럼·개발 글 — 2차): 3D 아이템을 칸마다 따로 실시간으로 돌리면 패스 수만큼 비싸다(Unreal 장면 캡처 20개+에서 프레임 급락). 흔한 답은 **아이콘은 한 번 찍어 두고(아이템마다 정한 각도)**, **고른 것 하나만 실시간으로 돌린다**. 한 번 찍기는 미리(오프라인) 또는 실행 중 처음 쓸 때(캐시) — RuneScape식 "아이템마다 정한 회전값으로 찍은 아이콘".

## 제안
1. **아이콘 = 실행 중에 한 번 찍어 캐시**: 인형과 같은 길(`draw_doll`의 작은 깊이 타깃 + 고정 카메라 + 같은 툰 빛·외곽선)로 아이템마다 32×32 안팎 타깃에 한 번 그려 두고, 칸 상자·후보 줄 왼쪽에 정수배로 붙인다. PNG 에셋이 늘지 않고(손으로 고칠 그림 없음), 모델을 고치면 아이콘이 저절로 따라온다.
2. **고른 것 하나는 돌려서 크게**: 설명 자리(창 왼쪽 아래)에 고른 아이템을 천천히 도는 3D로(타깃 하나 더 — 인형과 같은 값싼 패스). 글 설명은 그 옆으로.
3. **아이템마다 보는 각도는 표로**: `(이름, 부위·모델, 각도, 거리)` 한 줄씩 — 칼은 비스듬히 눕혀, 쇠뇌는 옆에서처럼 실루엣이 가장 잘 읽히는 각도(KB "실루엣 먼저"). 새 아이템 = 표 한 줄 + 모델.
4. **무기**: 이미 있다 — `wanderer.glb`에서 그 무기 부위만 그린다(손 뼈 자세를 빼고 부위의 쉬는 자리로).
5. **장신구 여섯**: 모델을 새로 만든다. Blender 스크립트(`tools/art/blender/charms.py`, `common.py`의 상자 + 둥근 덩어리, 0061 체크리스트 — 큰 색 덩어리·둥근 실루엣, 각진 것은 뿌리만) → `charms.glb` 한 파일에 장신구마다 부위 하나(이름 = 기록 키 `shell`·`feet`·`ear`·`hunger`·`hand`·`pouch`). 작게 보일 물건이라 Meshy보다 스크립트가 빠르고 고치기 쉽다. 그림 시안은 사장 확인.

| 장신구 | 생김새 시안(말) |
|---|---|
| 단단한 껍질 `shell` | 둥근 등딱지(갈색 + 밝은 테) |
| 가벼운 발 `feet` | 작은 깃털 달린 짚신 |
| 종지기의 귀 `ear` | 작은 놋쇠 종 + 귀 모양 고리 |
| 굶주린 뿌리 `hunger` | 보라 뿌리가 감은 이빨 모양 덩이(뿌리 = 각진 것) |
| 무거운 손 `hand` | 돌 장갑 |
| 잔불 주머니 `pouch` | 불씨가 비치는 천 주머니 |

## 비용·순서
1. 무기 아이콘 + 도는 미리보기(모델 있음) — 반나절.
2. 장신구 모델 여섯(스크립트) + 시안 스크린숏 → 사장 확인 — 하루 안팎.
3. 잠긴 장신구: 실루엣만(검게) 보일지, 아예 "?"일지 — 정할 것.

## 정할 것(사장)
1. 위 방식(아이콘 캐시 + 고른 것만 돌리기) — 추천.
2. 장신구 모델은 Blender 스크립트로(추천) / Meshy로.
3. 잠긴 장신구는 검은 실루엣(추천 — 무엇을 찾는지 기대하게) / "?" 칸.

## 구현(2026-11-05)
- **장비 창에서 못 얻은 장신구를 뺐다**: 후보 = 빈 칸 + 가진 것만(`equip::candidates(slot, owned)`, 시험). 0067의 잠긴 줄·얻는 곳 글 넷은 지웠다(도감이 생기면 거기서 실루엣 + 얻는 곳).
- **보기 표** `src/item_view.rs`: 아이템 → (모델, 부위, 각도) 한 줄씩. 무기는 `wanderer.glb`의 손 부위 — 모델 공간에서 날이 +z로 길고 넓은 면이 위(+y)라, 앞으로 세워(숙이기 −70~−80°) 넓은 면이 카메라를 보게 + 대각선으로 눕힘(쇠뇌는 T자 그대로). 처음엔 날의 얇은 쪽이 보여 칼이 막대 하나로 읽혔다. 시험: 부위 이름이 겹치지 않음(아이콘 캐시 열쇠), 모든 아이템의 부위가 모델에 있음(이름이 바뀌면 그림이 조용히 사라지니).
- **렌더** `Renderer::draw_icon`(32px 타깃에 한 번 찍어 캐시) · `draw_item`(56px 타깃 하나를 매 프레임 — 고른 것만) · 둘 다 `render_item`: 그 부위만(나머지 크기 0) 경계 상자 가운데로, 표의 각도 + **화면 세로축으로** 흔들기(모델 축으로 돌리면 세운 칼이 바퀴처럼 돌았다), 경계 구가 틀에 꽉 차게, 게임과 같은 툰 빛·외곽선. 화면에는 정수배(`icon_scale`)로만 — 도트가 고르게. `Model::rest_bounds_under`·`is_under`.
- **장비 창**: 칸 상자는 이름 대신 그림(디아블로 인형처럼), 고른 것은 아래에 크게 흔들리는 그림 + 이름(머리글) + 설명, 후보 줄마다 아이콘(`ui::Row::icon`·`Ui::list_icon`).
- **장신구 모델 여섯** `tools/art/blender/charms.py` → `assets/models/charms.glb`(정점 988 / 예산 1,800, `check_glb` 부위 여섯 확인, `build_all`에 넣음), 미리보기 `docs/art/previews/charms.png`. 첫 시안 — 껍질은 아직 납작한 빵처럼 보인다(사장 판정 뒤 다듬기).
- 확인: 단위 시험 210, 헤드리스 여섯, F4 넘침 검사 한국어·영어 0건, 스크린숏 `docs/art/ui-0068/`.

## 덧붙임: 설명 칸이 넘치면(2026-11-05)
- 사장: "넘치면 스크롤이갰지?" — 아니었다(세 줄까지만 그리고 나머지를 조용히 버렸다). 저절로 흐르게 하자는 제안에 "왜.. 흘러야해?" — 맞다: 읽는 속도를 빼앗고, 움직이는 글은 읽기 어렵다(WCAG 2.2.2 Pause, Stop, Hide), 넘침은 드물다(설명은 세 줄 안이 원칙). → **읽는 사람이 굴린다**.
- **패드** 오른쪽 스틱(메뉴에서는 쓰지 않던 축 — 위아래 목록과 겹치지 않는다, Microsoft "글만 있는 칸은 따로 굴리게"), **마우스** 휠·**터치** 끌기는 설명 칸 위에서 일어났을 때만 설명을(그 밖이면 후보 목록을 — `Actions::point` = 휠이면 마우스 자리, 끌기면 손가락이 처음 닿은 자리, `Hit::Pane`). 칸 고르기 창에는 굴릴 목록이 없어 휠·끌기는 어디서든 설명을.
- 굴림 값은 화면 공용 `App::scroll`(줄 단위, 장면이 바뀌거나 고른 것이 바뀌면 0), 한 걸음은 순수 `equip::pane_step`(시험: 손대지 않으면 그대로·끝에서 멈춤·넘치지 않으면 안 움직임).
- 넘칠 때만 ▲(위에 더)·▼(아래에 더)를 글 오른쪽에 — 그때만 오른쪽 자리를 비워 다시 나눈다(넘치지 않는 글은 폭을 다 쓴다; 늘 비워 두었더니 세 줄이던 영어 셋이 넘쳤다).
- 시험용 긴 글로 휠 굴리기를 스크린숏으로 확인하고 되돌렸다.
