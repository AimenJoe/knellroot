# 0075. 개발 메뉴 개편 — 묶음 탭(nail 0269 꼴), 개발 판은 기록을 쓰지 않음, 멈춤에 DEV

- 날짜: 2026-11-07
- 상태: **채택·구현**(개발판 전용)
- 사장: "멈춤 메뉴의 개발용 메뉴, 그쪽에서 여러 가지 테스트 할 수 있도록 한 거야? Nail 쪽 참조해 봐" → (제안) → "우리 쪽 메뉴 개편하자"

## nail에서 가져온 것(0269)
- 시작할 것을 **묶음**으로 나누고, 고른 줄의 **설명**을 보인다.
- 개발 판은 기록을 바꾸지 않는다. nail은 메모리에서만 바뀌고 슬롯을 다시 읽는다(B3).

## 결정
- **DEV 창**(`Scene::Dev { tab }`, `app/settings.rs`):
  - 줄은 차례로 **group** ◀ 묶음 ▶ · **weapon** ◀ 무기 ▶ · 그 묶음의 시작할 것들 · back이다.
  - 아래 설명 칸에 고른 줄의 설명이 나온다. 시나리오는 "아레나 숫자 키 n · 보는 것"이다.
  - 묶음은 0066대로 장면 칸의 상태다. 바꾸면 그 칸을 새 묶음으로 다시 연다.
  - 0066 줄 표(`Menu`) 그대로라 터치·마우스·▲▼ 굴리기가 같이 된다. nail처럼 탭 막대를 따로 그리지 않았다.
- **묶음**(`DEV_TABS`):

  | 묶음 | 시작할 것 |
  |---|---|
  | combat | 보스 아레나 · 기둥 + 보스 · 잔재 + 가시짐승 · 무리 20 · 쏟기 |
  | stage | 첫 스테이지 입구에서 · 문 앞(문지기) |
  | perf & tools | 빈 아레나 · 부하 40 · 부하 80 · 연구실 |

  - 시험 `every_scenario_sits_in_exactly_one_dev_group`: 새 시나리오를 묶음에 넣지 않으면 실패한다.
  - 첫 묶음 셋째 줄은 보스 아레나다. shot·mouse·leak 스크립트가 "아래로 둘 · 확인"으로 간다.
- **개발 판은 기록 슬롯에 쓰지 않는다**(`App::dev_run`, `persist`가 건너뜀).
  - stage 묶음에서 시작한 판은 지금 슬롯의 장신구·잔불로 진짜 스테이지를 돈다. 상자·잔불·도달 지점은 메모리에서만 바뀐다.
  - 슬롯을 고르면(`enter_slot` — 새로 하기·이어하기) 풀리고, 슬롯 것을 다시 읽는다.
  - 예전에는 문 앞 시작이 지금 슬롯에 그대로 썼다.
- **멈춤 창 끝에 DEV**(개발판만, `flow::pause_items()`): 판 중에 바로 개발 메뉴로 간다.
  - 다섯 줄 자리는 그대로이고, 끝에 붙였다.
  - 터치 시험 `menuRow`는 여섯 줄로 고쳤다.
- 개발 화면이라 글은 영어 그대로다(0013). 운영판(`--no-default-features`)에는 없다.
