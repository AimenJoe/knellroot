확인한 것:
- 시험 476 + 무시 2 그대로, 시험 이름 478개가 앞뒤로 같다(R3 뒤에는 `world::tests::<주제>::…`). `crate::render::…` 경로도 그대로라 render·world 밖의 파일은 한 줄도 바뀌지 않았다.
- fmt · clippy 다섯(wasm 개발판·운영판 · Android · Windows · iOS) · CI가 도는 브라우저 시험 넷(`shot`·`touch`·`pwa`·`save`) 통과.
- 화면: 가짜 시계로 한 프레임씩 흘려 찍은 650장(메뉴 · 스테이지 여섯 · 보스·엘리트 여덟 · 떼 · 쟁반 · 스킬 열하나)을 앞뒤로 견주었다. **메뉴는 빌드 해시 글자만 다르다.** 싸움 장면은 271장이 달랐는데, **같은(리팩터링 전) 빌드를 두 번 찍어도 71장 가운데 41장이 다르다** — 다른 픽셀의 평균이 같은 빌드끼리 0.93%, 앞뒤 0.59%. 곧 찍는 도구가 싸움 장면에서는 결정적이지 않고(브라우저 여러 개를 나란히 돌릴 때의 프레임 밀림으로 보인다 — 원인은 확인하지 않았다), 앞뒤의 차이는 그 잡음 안이다. 눈으로도 여섯 쌍을 나란히 보았다(윤곽선·그림자·예고·HUD가 같은 꼴).

### 지켜볼 것(지금은 그대로)
- **땅 돌리기**: 0151에서 십자 키·Z/C로 옮기고 쏟기를 남겼다. 스킬 여덟과 쟁반 뒤집기가 생긴 뒤에도 쓰이는지 — 판정에서 안 쓰이면 화면만 돌리는 것으로 줄이는 안이 있다.
- **성장의 겹 다섯**: 화로의 줄이 다섯(레벨·나무·가게·기술·떠나기). 나무(마디)와 기술 판(점수)을 한 화면의 두 탭으로 묶는 안 — 지금은 손대지 않는다.
- **내용의 양**: 지역 둘·보스 둘·종 여섯·엘리트 여섯에 스킬 여덟·큰 기술 셋(점수 23 / 48). 셋째 지역 전에는 A1로 있는 지역을 다시 짜는 쪽이 싸다.

### 먼저 볼 열 가지(사장 — 개발판에서 30분)
1. 스킬 넷을 끼워 가며 떼를 쓴다 — **재미있나**(16번 묶음의 한 줄).
2. 락온 보스전에서 스킬을 쓰면 패링·박자가 "안 해도 되는 것"이 되나.
3. 화로 → 기술: 판이 읽히나, 한 판 벌이로 무엇을 올릴지 계획이 서나(20-1·2).
4. 3단 고르기 둘이 다르게 싸우게 하나(20-3) — 휘돌이·땅울림만 봐도 된다.
5. 다 올린 스킬이 너무 센가(20-5).
6. 체력 막대가 읽히나, 눈금이 필요한가(19-1·2).
7. 십자 키·Z/C의 땅 돌리기를 아직 쓰나.
