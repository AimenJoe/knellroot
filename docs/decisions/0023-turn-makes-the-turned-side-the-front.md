# 0023. 땅 돌리기 = 돌린 쪽이 정면이 된다(캐릭터 기준)

- 날짜: 2026-11-03
- 상태: 채택·구현 → **0028이 고침**(화면만 버튼 쪽으로 늘 90°, 캐릭터는 그대로 움직임). 0017의 방향과 0020의 4번(위·아래로 뒤집기)을 대신한다.
- 사장: "캐릭터가 바라보는 방향에서 RB 누르면 해당 방향으로 턴한다는 생각으로 돌아가야 하지 않을까?" → 그림 셋을 보여 묻자
  "진행 방향에서 오른쪽 버튼 누르면 화면이 오른쪽으로 90° 돈 상태로 내가 직진할 수 있는 상태인 거지. 버튼 누르기 전의 캐릭터 기준 오른쪽 면이 정면이 되도록".

## 무엇이 틀렸나
- 0017의 "RB = 카메라가 오른쪽으로"는 카메라 **몸통**이 오른쪽으로 도는 것(요 +90°)이라, 보이는 쪽은 왼쪽으로 돈다 — 위를 보고 RB를 누르면 **왼쪽에 있던 것이 정면**이 됐다. 위·아래로 걸을 때 반대로 느낀 것(0020)은 여기서 왔고, 0020은 위·아래로 뒤집기만 해 아래를 볼 때만 맞았다.
- 캐릭터 몸은 돌지 않고, 쥔 스틱은 돌기 전 기준을 붙잡아(0010의 규칙을 돌리기에도 썼다) 돌린 뒤 바로 직진할 수 없었다.

## 결정
- **오른쪽 버튼 = 누르기 전 캐릭터의 오른쪽 면이 새 정면**(왼쪽 버튼은 거울). `world::plan_turn`: 바라보는 쪽에서 오른쪽 90°를 지금 화면의 네 방향(위·왼쪽·오른쪽·아래) 중 가장 가까운 것으로 맞추고, 그쪽이 화면 위가 되게 카메라가 돈다.
  | 누르기 전 바라보는 쪽 | 오른쪽 버튼 → 카메라 | 왼쪽 버튼 → 카메라 |
  |---|---|---|
  | 화면 위 | 오른쪽으로 90°(요 -90°) | 왼쪽으로 90° |
  | 화면 아래 | 왼쪽으로 90° | 오른쪽으로 90° |
  | 화면 오른쪽 | 180°(오른쪽으로) | 그대로(몸만 위로) |
  | 화면 왼쪽 | 그대로(몸만 위로) | 180°(왼쪽으로) |
- 캐릭터는 돌아서는 동안(`turn.plant s`) 새 정면으로 몸을 돌린다. 쥔 스틱은 **곧바로 새 정면 기준**(락온을 풀 때의 0010 붙잡기는 그대로).
- 180°는 `TURN_HALF_MUL`(1.6)배 길게, 정한 쪽으로(카메라 보간의 "짧은 쪽"이 180°에서 뒤집히지 않게 `Curve::Over`가 방향을 든다). 몸만 돌 때는 `turn.camera s × TURN_SPIN_ONLY`(0.4) 뒤에 쏟는다.
- 쏟는 쪽 = 카메라가 도는 쪽(몸만 돌 때는 몸이 도는 쪽). 이벤트는 `Event::Turn { quarters }`(−2..2), 입력 이름은 `turn_right`·`turn_left`(시계·반시계가 아니라 버튼의 좌우가 뜻).
- 시험: `the_side_you_turn_to_becomes_the_new_front`, `turning_turns_the_body_to_the_new_front`, `after_a_turn_the_held_stick_walks_straight_to_the_new_front`, `a_half_turn_goes_the_chosen_way_and_ends_half_round`. 헤드리스 스크린숏으로 확인: 위로 걷다 E → 오른쪽의 뿌리 덤불이 화면 위, 왼쪽의 기둥이 등 뒤, W로 그쪽 직진.

## 배운 것
- 방향 요청은 "버튼을 누르면 무엇이 어디로 가는가"로 물어야 한다(0017에서 적어 두고도 "카메라가 오른쪽으로"라는 말로 물었다 — 카메라 몸통과 보이는 쪽이 반대라 뜻이 갈린다). 이번엔 장면 그림(문·기둥·캐릭터)으로 물었다.

## 다시 볼 조건
- 옆을 볼 때의 180°·"몸만"이 헷갈리면: 늘 90°만 돌고 캐릭터만 새 정면을 보게(옆을 볼 때 정면 = 지금 화면 위·아래 중 가까운 쪽).
