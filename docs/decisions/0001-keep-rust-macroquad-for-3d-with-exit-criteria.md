# 0001. 3D도 Rust + macroquad로 — 단, 출구 조건을 적어 둔다

- 날짜: 2026-11-03
- 상태: 채택(사장, ChatGPT 브레인스토밍 2026-11-03: "게임 엔진(개발스택)은 그대로 쓰려고 해")

## 배경
- 첫 게임(nail)이 Rust + macroquad로 웹·PC·Android·iOS 빌드와 CI·입력 래치·패드 패치·웹 셸을 갖췄다. 이것을 버리면 플랫폼 작업을 처음부터 다시 한다.
- ChatGPT는 Godot/Unity를 권했다(카메라 블렌딩·애니메이션·에디터). 맞는 말이지만 그 이점은 "리얼한 3D"에서 크고, 레트로 상자 모델에서는 작다.
- macroquad의 3D는 카메라 행렬 + 즉시 모드 삼각형까지다(KB `reference/macroquad/3d-rendering.md`, 소스로 확인): 모델 로더·스키닝·조명·그림자·카메라 충돌 없음, 정점은 매 프레임 재업로드, 기본 셰이더는 normal을 안 읽음.

## 결정
- 스택 유지. 그 대신 **그림의 상한을 엔진에 맞춘다**: 상자 + 부위 강체 애니메이션(스키닝 없음), 아틀라스 텍스처 하나, 조명은 정점 색 또는 램버트 한 줄 커스텀 머티리얼, 그림자는 바닥 원판.
- 첫 게임에서 가져오는 것: 입력 래치·패드, 고정 틱, 렌더 타깃 정수 배율, 웹 셸·JS 번들, CI, prefs/profile, 운영판/개발판 feature. 2D 전용(스프라이트 시트·타일·지형 굽기)은 안 가져온다.
- **출구 조건**(`docs/phase-0-poc.md`): P4(모델 파이프라인)를 2026-11-24까지 못 닫거나 P5(떼 + 보스 웹 60fps)가 아틀라스·한 배치로도 안 되면 Fyrox(에디터·glTF·스키닝 내장) 또는 Bevy를 **그때** 검토한다. 그 전에는 엔진 논의를 다시 열지 않는다.

## 왜
첫 게임의 교훈: 플랫폼 리스크는 콘텐츠 전에 스파이크로 재고, 일주일 안에 안 끝나면 바꾼다(KB `rust-game-engines`). 이번 리스크는 "3D 모델·애니메이션 파이프라인"이고, 상자 모델이면 그 리스크가 로더 하나(glTF 노드 트리 + 채널)로 줄어든다.

## 확인
- P1~P5 판정표. 이 PoC는 P1·P2·P3의 코드를 다 담고 있고(상자), 실기 판정은 사람이 한다.

## 다시 볼 조건
출구 조건 둘 중 하나. 또는 "마인크래프트보다 조금 정교"가 "진짜 로우폴리 캐릭터(스키닝)"로 바뀌면.
