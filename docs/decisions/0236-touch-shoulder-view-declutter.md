# 0236 — 숄더뷰 터치 버튼 덜어내기 · 버튼 위에서 끌어도 시점 · 터치 버튼 크기 설정

- 날짜: 2026-11-18
- 상태: **결정 + 만듦**(개발판 `release/v0.7`, 판정 전)
- 사장: "터치스크린에서 버튼 크기가 좀.. 숄더뷰에서 화면 돌리기 어렵게 많고 크네..? 뭔가 잘 정리 할수 있으려나? 버튼이 큰 다른 게임들은 어떻지"

## 무엇이 문제였나(헤드리스 폰 화면 844×390으로 셈)
- 숄더뷰에서 오른쪽에 늘 떠 있던 것: 공격 · 첫째 호 넷 · 스킬 칸 둘(배운 것이 없어도 빈 테) · 땅 돌리기 둘 · 시점 · (적이 가까우면) 락온 = **열하나**.
  공격 지름 0.27u, 둘째 호까지 오른쪽 아래 ⅓을 버튼이 덮어, 시점을 끌 빈 자리(오른쪽 반의 버튼 아닌 곳)가 화면 위쪽 띠뿐이었다.
- 땅 돌리기(90°)는 쿼터뷰의 것이다 — 숄더뷰는 끌기가 시점이고, 락온 중에는 월드가 돌리기를 막는다(`try_turn`). 쓸 수 없는/쓸 일이 없는 버튼이 떠 있었다.

## 다른 게임은(조사 — KB `touch-action-layout`)
- **Epic(Fortnite) 모바일 설계 지침**(1차): 한 번에 보이는 컨트롤은 5~6개까지, 하는 일에 따라 펼치고 접는 HUD, 버튼을 늘리기보다 상황 동작, 최소 44×44pt.
- **Apple HIG Game controls**(1차, 0053에서 읽음): 쓸 수 없거나 상관없을 때는 숨겨 어수선함을 줄여라.
- **CoD Mobile**(Activision 블로그, 1차): 커스텀 레이아웃에서 모든 화면 요소의 크기·불투명도를 바꾼다, 시점은 화면 오른쪽 아무 데나 끌기.
- **Warzone Mobile**의 "Fire Button Allows Rotation"(쏘기 버튼으로도 시점 돌리기) — 2차(공략 글 검색 요약, 원문 403으로 못 읽음).
  PUBG Mobile의 쏘기 버튼 끌기 = 시점(2차, 0229).

## 고침
1. **상황 숨김**(`touch::Ctx::hide_turn`·`bare`, 앱이 매 프레임): 땅 돌리기 둘은 쿼터뷰 + 락온 아닐 때만, 스킬 칸은 끼운 스킬이 있을 때만
   (든 무기로 못 쓰는 칸 — 배운 것은 있다 — 은 흐린 그림으로 남는다, 0223 V3). 자리는 비워 둔다(0053 — 다른 버튼을 밀지 않는다).
   → 숄더뷰 기본 오른쪽 버튼 = 공격 + 넷 + 시점 = **여섯**(Fortnite 지침의 끝), 락온·스킬·등잔·바꾸기는 쓸 수 있을 때만.
2. **버튼 위에서 끌어도 시점**(숄더뷰만, `touch::Rider`): 버튼을 누른 손가락은 그 일을 그대로 하고(쥐면 강타 모으기·달리기·막기도 그대로),
   탭 범위(24px)를 넘게 끌면 그 뒤로 끈 만큼 시점이 돈다 — 넘는 순간 튀지 않게 탭 범위 안의 움직임은 버린다(연타하는 엄지가 화면을 흔들지 않게).
   겨누는 버튼(0229 — 탄·한 대상 스킬)은 이미 그랬고, 땅 위에 겨누는 버튼(수류탄·범위 스킬)은 0230대로 땅 위 끌기라 빠진다. 멈춤은 빠진다.
3. **터치 버튼 크기**(설정 탭, 터치가 주인인 기기에서만 — 마우스 줄과 엇갈린다): 80 · 90 · 100 · 115%. 엄지 묶음(공격·호·스킬·상황 버튼)의 크기와
   공격 쪽 모서리에서의 거리가 같은 배로 — 겹치지 않는다. 위 가장자리 줄(멈춤·시점·돌리기)은 그대로. prefs 칸 35(뒤에 붙인 칸 — 옛 저장 = 100%).
   가장 작게(80%)도 가장 작은 가로 폰(667×375)에서 가장 작은 버튼 지름이 35px(44pt의 0.8) 위 — 시험이 본다.

## 하지 않은 것
- 기본 크기는 그대로(100%) — 엄지가 외운 자리와 크기를 사람 판정 없이 바꾸지 않는다. 작게가 낫다면 판정 뒤 기본값을 옮긴다.
- 버튼마다 자리 옮기기(CoD식 커스텀 레이아웃)·불투명도 — 화면 하나가 더 드는 일이라 판정을 보고.
- 숄더뷰 전용 배치(버튼을 다른 자리로) — 손이 외운 자리가 보기마다 달라진다(0053 원칙).

## 시험
- `touch.rs`: `the_shoulder_view_hides_the_turn_pair_and_empty_skill_slots`(숨겨도 나머지 자리 그대로, 숄더뷰 기본 = 여섯) ·
  `a_smaller_touch_size_shrinks_the_thumb_cluster_toward_the_corner` · `a_finger_on_a_button_turns_the_view_only_after_it_leaves_the_tap_slop` ·
  겹침·화면 안 시험을 크기 단계마다 · 최소 크기 시험을 80%에서도.
- `flow.rs`: 크기 줄은 마우스 없는 기기에서만.
- 헤드리스 `tools/test/touch.js`: 숄더뷰 화면(t01b — 돌리기·빈 스킬 칸이 없다) · 패링 버튼을 누른 채 끌어 시점이 돈다(t01c3) · 돌리기 전에 락온을 푼다.

## 판정 거리
- 숄더뷰에서 오른손으로 시점을 돌리기가 편해졌나(빈 자리 끌기 · 공격/회피를 쥔 채 끌기). 연타 중에 화면이 흔들리지 않나.
- 버튼 크기 80·90%가 엄지에 맞나 — 기본을 옮길까.
