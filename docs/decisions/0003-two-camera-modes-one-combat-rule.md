# 0003. 카메라 모드 둘, 전투 규칙 하나 — 입력 기준은 즉시, 카메라만 보간

- 날짜: 2026-11-03
- 상태: 채택(사장: 락온은 플레이어가 직접, 두 모드 모두 Perspective). 수치는 랩 판정 전(초기값).

## 결정
- `World`는 카메라를 모른다. 모드에 따라 다른 것은 셋뿐: 카메라 리그, 타깃팅(락온), 입력 기준(`Basis`).
- 락온 버튼을 누른 **그 틱**에 입력 기준이 대상 기준으로 바뀐다(앞 = 대상, 옆 = 둘레). 카메라는 0.3초 동안 따라온다.
- 두 리그 모두 Perspective. 쿼터뷰 FOV 42°(디아블로식 15~20°는 숄더뷰 58°와 격차가 커 멀미), 위치·주시점·FOV를 같은 smoothstep 곡선으로.
- 락온 구도: 카메라는 플레이어 뒤 4.5·위 2·어깨 0.8, 주시점은 플레이어↔대상 0.4 지점 **+ 옆으로 1.0**. PoC에서 확인: 어깨 오프셋만으로는 플레이어가 화면 가운데에 남는다(각도 ≈ atan(0.8/4.5) ≈ 10°). 주시점을 옆으로 밀어야 1/3 구도가 된다(시험이 NDC x < -0.15를 본다).
- 가림: 머리→카메라 선분이 상자에 막히면 그 앞으로 당긴다(반지름 0.3). 머리에서 1.2보다 가까이는 안 오고, 가까우면 플레이어를 옅게. 지형 페이드는 P2 판정 뒤 필요할 때만.
- 락온 대상 고르기: 거리/범위 + (1 - cos 각)·0.5 - 보스 0.5. 풀림: 버튼·사망·26m.

## 왜
KB `concepts/camera-mode-switch-and-lock-on.md`(Nesky 50 실수 1~25, 친구의 조언, ChatGPT 제안). 카메라는 실패할 때만 보이고, 전환마다 실패 지점이 생긴다. 규칙 하나 + 리그 둘이면 실패 지점이 전환 함수 하나로 모인다.

## 확인

- 헤드리스 스크린숏 `shots/02~04, 08, 10`(전환 중간·락온 구도·스트레이프·해제·기둥 당기기).
- **사람이 볼 것**: 멀미·"우왁"·전환 중 조작 꼬임(P2), 전환 0.2/0.3/0.45와 frame x 0.5/1.0/1.5 A/B.

## 다시 볼 조건
