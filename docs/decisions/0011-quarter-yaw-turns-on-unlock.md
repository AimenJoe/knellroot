# 0011. 쿼터뷰 방위를 락온 해제 때 돌린다 — 고정 / 따라감 / 90° 단위(기본)

- 날짜: 2026-11-03
- 상태: 채택·구현(사장: "다른 게임에서는 어떻게… 아니면 월드 자체의 yaw를 돌리는 건 어떤가?" → 세 방식을 랩에 넣고 비교해 배포).

## 다른 게임(2차 출처: 리뷰·인터뷰·분석 글, 직접 해 보지 않음)
- 쿼터뷰 소울라이크는 대개 락온해도 카메라가 고정이다. Tunic은 Z타깃(캐릭터만 대상을 보고 옆걸음, 리뷰마다 카메라 변화 서술이 엇갈림), Death's Door는 한 각도.
- Achilles: Legends Untold는 개발 첫 해를 "쿼터뷰 + 락온 결합"에 썼다고 했지만 리뷰에서 가장 많이 지적된 것이 락온이다(불안정·여러 적 사이에서 방해, 끄고 하는 편이 낫다는 평).
- NieR: Automata는 시점을 바꾸지만 연출 구간에서 고정 전환이지 플레이어 버튼이 아니다.
- 결론: 플레이어가 쿼터뷰 ↔ 숄더뷰를 버튼으로 오가는 본보기는 찾지 못했다 — 이 게임의 차별점이자 위험. 그래서 재서 고른다.

## 결정
- `cam.quarter.yaw mode` — **0 고정**(예전, 늘 35°), **1 따라감**(해제 때 락온하던 방향 그대로), **2 90° 단위(기본)**(35° + 90°×k 중 락온 방향에 가장 가까운 것 — 최대 45°만 돌고 지도 방향은 넷).
- 카메라가 지금 방위를 갖고(`quarter_yaw_deg`), 앱이 매 틱 월드에 넘긴다(`World::view_yaw`) — 입력 기준 "화면 위"가 카메라와 늘 같다. 월드는 여전히 카메라를 모르고 숫자 하나만 받는다.
- 0010의 "쥔 스틱 그대로"는 그대로 — 따라감 방식에서는 풀린 뒤 쿼터뷰 화면 위가 그 방향과 같아진다.

## 잰 것(`camera::yaw_mode_probe`, 보스 둘레 8방향, 락온 → 해제 → 다시 락온)
| 방식 | 들어갈 때 최대 | 해제 최대 | 해제 걸리는 시간 최대 | 다시 들어갈 때 최대 |
|---|---|---|---|---|
| 고정 | 260°/s | 332°/s | 0.77초 | 260°/s |
| 따라감 | 260°/s | 228°/s | 0.30초 | 160°/s |
| **90° 단위** | 260°/s | 244°/s | 0.35초 | 174°/s |

해제 때 남은 회전(228~244°/s)은 방위가 아니라 고개 들기(−7° → −54°)다 — 짧게 끝나서(0.3초) 빠르다.

## 확인
- 시험 `snap_and_follow_turn_less_on_release_than_fixed`(90° 단위 해제 최대 < 고정의 0.8배, 따라감 ≤ 90° 단위). 0007~0010 시험 그대로 통과.
- 헤드리스: 해제 전환 중 화면이 보스 쪽을 향한 채 높아진다(예전엔 35°로 돌아가며 보스가 화면 밖).
- **사람이 볼 것**: 세 방식을 랩에서 바꿔 가며(값 0/1/2) — 해제 뒤 지도 방향이 바뀌는 게 길 찾기에 거슬리는지(따라감이 가장 크다), 90° 단위의 45° 회전이 괜찮은지. 쿼터뷰 방위를 돌린 뒤 고정으로 되돌리려면 랩에서 값을 0으로.

## 다시 볼 조건
방이 이어지는 구역(문·통로)이 생기면, 돌아간 방위와 방 짜임이 어긋나 길이 대각으로 보일 수 있다 — 그때 "싸움이 끝나면 천천히 기본 방위로" 되돌리기를 검토.
