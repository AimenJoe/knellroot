# 0010. 락온을 풀 때 — 쥔 스틱은 그대로, 쿼터뷰로는 더 빨리

- 날짜: 2026-11-03
- 상태: 채택·구현(사장: "1+3으로 진행하고 배포해줘"). 0003의 "입력 기준은 즉시 바꾼다"를 해제 쪽에서 고친다.

## 잰 것(보스 둘레 8방향, 전환 동안 "스틱 위"가 실제로 가는 월드 방향과 화면 위의 각도 차)
들어갈 때와 나올 때 카메라 움직임은 같았다(150~260°/s). 다른 것은 조작이었다: 풀자마자 스틱이 쿼터뷰 기준으로 바뀌는데 화면은 최대 1.1초 숄더뷰에서 돌아오는 중 — 차이가 최대 **172°**. 락온 중에는 보통 움직이고 있으니(대상 둘레·물러나기) 쥔 그대로의 스틱이 풀리는 순간 거의 반대쪽을 가리켰다. 들어갈 때는 "앞 = 대상 쪽"이 원래 의도라 거슬리지 않았다.

## 결정
1. **쥔 스틱은 그대로**(`Basis::Frozen`): 락온이 풀리는 틱(버튼·대상 사망·거리)에 스틱을 0.3보다 세게 쥐고 있으면, 풀던 순간의 락온 앞(대상 쪽)을 기준으로 계속 걷는다. 스틱을 놓거나 `move.hold after unlock s`(0.6초)가 지나면 쿼터뷰 기준. 바라보기는 쿼터뷰처럼 걷는 쪽.
2. **쿼터뷰로는 더 빨리**: 해제 전환 길이 × `cam.blend exit x` **0.7**(0.28~0.84초). 0.5도 재 봤으나 해제 회전이 464°/s까지 올라 멀미 쪽이었다(0.6 → 387, 0.7 → 332, 0.8 → 290°/s).

## 확인
- 시험 `releasing_lock_while_holding_the_stick_keeps_walking_the_same_way_until_the_stick_is_let_go`(보스 위쪽에서 물러나다 쥔 채 풀어도 걷는 방향 내적 0.98 이상, 놓았다 다시 쥐면 쿼터뷰 기준), `the_unlock_hold_ends_by_itself_after_the_hold_time`, `going_back_to_quarter_view_is_faster_than_locking_on`, 0009 시험(최악 340°/s 안 — 해제 쪽).
- **사람이 볼 것**: 보스에게서 물러나며(스틱 아래) 락온을 풀 때 캐릭터가 계속 같은 쪽으로 가는지, 스틱을 놓았다 다시 쥐면 화면 기준으로 돌아오는지. 해제가 아직 느리면 `cam.blend exit x` 0.6, 멀미면 0.8. 0.6초 뒤 저절로 바뀌는 순간이 거슬리면 `move.hold after unlock s`를 늘린다.
