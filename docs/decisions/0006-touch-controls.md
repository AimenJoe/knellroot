# 0006. 터치 조작 — 가상 스틱 + 버튼 셋, 랩은 한 줄 터치판

- 날짜: 2026-11-03
- 상태: 채택·구현(사장: "응 터치스크린 넣고 배포해줘"). 0005의 v0.1.0 조건 4("터치는 안 돼도 된다")를 넘어 v0.1.0에 넣는다.

## 결정
- **카메라를 손으로 돌릴 일이 없다**(쿼터뷰 요 고정, 락온은 카메라가 대상을 따라감) → 오른쪽 엄지 카메라 조작이 없다. 3D 액션이 터치에서 어려운 가장 큰 이유가 처음부터 없다.
- 왼쪽 반 = 떠다니는 가상 스틱(댄 자리가 중심, 데드존 0.15). 오른쪽 아래 = 공격(지름 ≈ 짧은 변 27%)·회피(왼쪽 아래)·락온(위, 걸려 있으면 노랗게 참). 글자 대신 선 그림(칼·겹 화살촉·조준 고리).
- dev 기능: 오른쪽 위 SC(다음 시나리오)·LAB. 랩이 열리면 HUD 아래 한 줄: ▲ ▼ − + R(초기화) B(담기) A/B(바꾸기), −+는 누르고 있으면 반복(0.35초 뒤 0.06초마다). 값 이름·현재 값·슬롯은 줄 바로 위 한 줄(오른쪽 위 버튼에 닿으면 글자를 줄인다). 내보내기(E)는 폰에 콘솔이 없어 뺐다 — 화면의 값을 보고 알려 주면 된다.
- 장치는 마지막으로 만진 것(nail 0036). 오버레이는 장치가 터치일 때만, 키·패드를 만지면 사라진다. 첫 화면은 `pointer: coarse`(JS 플러그인 `knell_device`)로 미리 정한다.
- 터치 장치에서는 HUD의 키 안내·검증 항목 줄을 뺀다(손가락에 안 맞는 글, 랩 줄 자리).
- **정수 배율을 물리 픽셀로 센다**: 폰(DPR 3, 논리 844×390)에서 논리로 세면 1배(480×270)라 화면 절반이 검정이었다. 물리 2532×1170 → 4배 → 논리 640×360. 데스크톱(DPR 1)은 전과 같다.

## nail에서 가져온 것과 그 까닭
`read_touch`·`TouchOverlay`(nail `src/input.rs`, 0172·0199). 함정 둘을 그대로 피했다: `touches()`만 물리 픽셀이라 DPI로 나눈다, `TouchPhase::Started`가 같은 프레임의 Moved에 덮이므로 처음 보는 id를 눌림으로 본다. `simulate_mouse_with_touch(false)`.

## 확인
- 시험: `buttons_stay_on_screen_and_do_not_overlap_on_phone_tablet_and_desktop`(가로 폰 둘·태블릿·데스크톱·세로 폰 × 랩 열고 닫고), `attack_is_the_biggest_button_and_meets_the_minimum_touch_size`, `stick_has_a_dead_zone_points_up_when_the_finger_goes_up_and_saturates`.
- 헤드리스 터치 연기 시험 `tools/test/touch.js`(844×390, DPR 3, CDP 터치 끌기): 첫 화면 버튼, 스틱 걷기, 두 손가락(스틱 + 공격), 락온(버튼 노랗게), 회피, 랩 ▼·+·담기·−·바꾸기, 다음 시나리오. 콘솔 에러 0. CI에서도 돈다.
- **사람이 볼 것**: 실제 폰 브라우저(iPhone Safari·Android Chrome)에서 엄지 자리·버튼 크기, 락온 구도에서 왼손 엄지가 플레이어를 가리는지(`cam.lock.frame x`), 회피 타이밍이 터치로 할 만한지. 헤드리스 fps 20대는 GPU 없는 소프트웨어 렌더라 실기 수치가 아니다.
