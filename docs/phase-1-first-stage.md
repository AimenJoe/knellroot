# 1단계: 첫 스테이지 초안 — "침묵의 성소"

PoC를 닫고(0019) 이야기 첫 장을 한 판으로 만든다. **초안이다** — 그림·소리·수치는 모두 바뀐다. 목적은 (1) 장면·스테이지·종류·글·모델이 표와 파일로 늘어나는 뼈대가 서는지, (2) 쿼터뷰 떼싸움 → 문 → 락온 보스전이 한 판 안에서 이어지는지 보는 것.

## 범위
- 장면: 타이틀(시작·언어·개발판 항목 둘) → 시작 이야기 → 싸움 → 멈춤(계속·처음부터·타이틀로) → 끝(1.6초) → 결과(클리어 = 시간·쓰러뜨린 수 / 쓰러짐)
- 스테이지: 입구 → 좁은 길 → 뿌리의 뜰(물결 셋) → 성소 문 → 잠든 문지기 깨어남 → 결투 → 핵 거두기
- 적: 뿌리의 잔재(느린 근접 떼), 가시짐승(곧은 돌진), 잠들지 않는 문지기(보스: 부채꼴 내려치기·돌진·뿌리 파동, 반 아래에서 빨라짐)
- 그림: 바닥 석판·무너진 벽·기둥·뿌리·화로 불빛(정점 빛), Blender 모델(방랑자·잔재·가시짐승·문지기·소품), 예고 모양 넷(원판·부채꼴·띠·고리)
- 글: 한국어·영어(고운바탕 서브셋, 0021), 키 그림은 지금 장치에 맞춰
- 하지 않는 것: 소리, 저장, 스테이지 둘째, 레벨 편집기, 개발 메뉴 안의 랩(랩은 F1 그대로)

## 판정(사람)
| # | 질문 | 기준 |
|---|---|---|
| S1 | 한 판이 이어지나 | 처음 하는 사람이 설명 없이 입구 → 뜰 → 문 → 보스 → 핵까지 간다(어디로 가야 할지 헤매지 않는다) |
| S2 | 뜰에서 쿼터뷰 떼싸움이 읽히나(P1 이어서) | 잔재와 가시짐승을 구분하고, 돌진 띠를 보고 피한다 |
| S3 | 보스전이 락온으로 할 만한가(P3 이어서) | 예고 셋(부채꼴·띠·고리)을 읽고 피한다. 2~4분 안에 이기거나 질 이유를 안다 |
| S4 | 분위기 | 어둡고 조용한 성소 + 호박색 불빛. 캐릭터가 바닥에 묻히지 않는다 |
| P5 | 실기 성능(PoC에서 넘어옴) | 뜰 셋째 물결에서 데스크톱 Chrome 60, Android Chrome 30 이상(개발 줄 F3) |

## 사람이 할 일
- [ ] **웹 로딩·PWA(0062)**: 개발판 주소를 폰(Android Chrome)에서 "홈 화면에 추가" → 아이콘 모양, 가로 전체 화면으로 뜨는지, 비행기 모드로 다시 열리는지. 느린 회선에서 종·막대가 괜찮은지.
- [ ] **굴리는 목록(0059)**: 지금은 넘치는 메뉴가 없어 볼 것이 없다 — 줄이 늘어 굴리기가 켜지면 폰에서 끄는 빠르기·탭 범위.
- [ ] **키보드+마우스(0058)**: 실제 마우스로 — 오른쪽 클릭 마법이 커서 쪽으로 가는지, 커서를 멈춘 1초 뒤 자동 조준으로 돌아가는 게 어색하지 않은지(설정 0.5~4초), 걸을 때 몸이 커서를 보는 게 괜찮은지, 조준 표시 크기, L-Shift 패링 타이밍이 손에 맞는지, 휠 클릭 락온. 옛 저장이 있는 브라우저는 키보드만 배치 그대로라 조작 설정에서 "키보드+마우스 배치로"를 눌러 봐야 한다.
- [ ] **캔슬(0057)**: 공격 → 회피·패링·점프, 회피 → 공격·점프가 손에 붙는지. 망치가 "몸을 맡기는" 무게로 느껴지는지(너무 굳으면 무기 표 `cancel`을 낮춘다), 회피 뒷부분 끊기(0.7)가 무적을 너무 줄이지 않는지.
- [ ] **원거리 강공격(0056)**: RB를 쥐어 모으는 0.7초가 길거나 짧지 않은지(랩 `cast.charge s`), 모은 탄이 시원한지, 칸·볼트 하나를 더 쓰는 값이 맞는지.
- [ ] **무기 넷(0051)**: 멈춤 → 무기로 바꿔 가며 — 검 3연타 이음, 망치의 무게(느린 2타·여진 타이밍), 지팡이 딱 맞춘 떼기 창(0.15초), 쇠뇌 탄창 4·장전 1.2초·수류탄 도화선 1.5초가 손에 맞는지. 자세 깨기가 보스에게 너무 쉽거나 어렵지 않은지, 깬 뒤 폭딜(×1.5, 보스 1초)이 시원한지(랩 `poise.*`), 쇠뇌 X 꾹 겨누기.
- [ ] **설정·DEV(0052)**: 타이틀·멈춤에서 설정이 찾기 쉬운지, 흔들림 줄이 효과가 있는지.
- [ ] **터치(0053)**: 폰에서 덜 난잡한지, 둘레 넷이 엄지에 닿는지, 상황 버튼(락온·등잔)이 뜨는 때가 맞는지. 다음 단계(쓸어서 돌리기·마법 끌어 조준·버튼 크기 설정)를 할지.
- [ ] **글자(0049·0054)**: 폰·핸드헬드에서 전체 화면을 여러 번 켜고 꺼도 글자가 검게 되지 않는지.
- [ ] **락온 구도(0050)**: 높인 숄더뷰(19°)에서 거리 재기가 나아졌는지, 방랑자가 보스를 가리지 않는지 — 랩 `cam.lock.height`·`shoulder`·`frame x`.
- [ ] **새 배치·마법(0048 1단계)**: RB 마법을 오른쪽 스틱으로 겨누며 쏘기가 손에 맞는지, 칸 3·근접 4대에 1칸이 너무 짜거나 후하지 않은지(랩 `cast.per hit`), 탄이 화면에서 보이는지, 등잔 Y·A로 쉬기가 헷갈리지 않는지, RB를 누르다 RT(돌리기)가 잘못 들어가지 않는지. 다음은 무기 표(X·RB 짝 — 근접 무기 = X 콤보 + RB 마법, 원거리 무기 = RB 사격 + X 수류탄).
- [ ] **전체 화면(0046)**: 핸드헬드(Android 11+)에서 상태·내비게이션 바가 숨는지, 가장자리를 쓸면 잠깐 나왔다 들어가는지. 웹은 브라우저 창에서 테두리 없이 꽉 차는지, 타이틀 "전체 화면" 줄, 폰에서 "시작"을 누르면 전체 화면 + 가로가 되는지.
- [ ] **모으며 걷기·공중 돌기(0047)**: 모으는 동안 ×0.4 걷기가 너무 빠르거나 느리지 않은지(랩 `heavy.charge walk x`), 점프 중 몸 돌리기로 내려찍기를 겨눌 수 있는지.
- [ ] **빛·그림자(0044·0045)**: 달이 왼쪽 앞에서 오는 해 질 녘 분위기·픽셀 그림자가 마음에 드는지, 화면이 너무 어둡지 않은지. **핸드헬드에서 개발 시나리오 7(잡몹 80)** cpu·fps를 `render.actor shadow` 1/0으로.
- [ ] **높낮이(0043)**: 성소의 단·경사로·꺼진 광장이 싸움에 재미를 더하는지(디딤단·높은 단으로 피하기가 너무 쉽지 않은지), 턱이 화면에서 읽히는지, 0.5m 턱 점프가 손에 맞는지.
- [ ] **해상도 640×360(0041)**: 핸드헬드에서 화면이 꽉 차는지, 글이 같은 크기로 읽히는지, 개발 시나리오 7(잡몹 80) cpu·fps가 버티는지. 쿼터뷰 카메라 각은 랩 `cam.quarter.pitch`를 35° 안팎으로 보고 정하기.
