# v0.5.0 T2 구현 분석 — 지역 환경(0119)

- 분석 기준: `release/v0.5` HEAD `5cd1f8a7bd25bb5c5e54da020e58861f9ed6704d`
- 기준 상태: PR #10 머지(`489d3eb0d0dc8fb9a2972805966e5a4103f491f6`) 이후, `main`의 v0.4.2 변경을 `release/v0.5`에 병합한 상태
- 정본: `docs/decisions/0116-v0-5-0-milestone.md` T2, `docs/decisions/0119-region-environment.md`
- 범위: T2 지역 환경만 분석. T3 구역 등급 및 C1/C2/C7 콘텐츠는 별도 분석 대상.
- 판정: **핵심 기능은 구현되어 있으나, 떨어지는 흙의 높이 기준은 수정 필요. 환경 회귀 테스트도 보강 권장.**

## 1. 요구 사항과 구현 대조

| 0119 요구 | 구현 위치 | 확인 |
|---|---|---|
| 지역별 환경을 `StageDef::env` 한 필드로 선택 | `src/stage/mod.rs`, `src/stage/village.rs`, `src/backdrop.rs` | 구현 |
| 성소의 해 질 녘 하늘·달·산등성이·뿌리 아치 | `backdrop::SURFACE`, `Backdrop::sky/ridges` | 구현 |
| 마을의 흙빛 하늘·달 제거·동굴 벽·뿌리 천장 | `backdrop::UNDERGROUND`, `ridge_h = 2.2`, `Backdrop::ridges` | 구현 |
| 지하 달빛 0.4 | `Env::moonlight` → `render::set_moonlight` → `lit` | 구현 |
| 안개 색 지역화 | `Env::fog/fog_deep`, `Renderer::draw` | 구현 |
| 지하 반딧불 제거, 먼지·떨어지는 흙 표시 | `Backdrop::motes`, `Env::fireflies/falling` | 구현 |
| 지하 나무·덤불 제거, 벽 뿌리 유지 | `Scenery::bake(..., trees)` | 구현 |
| 천장 틈 빛줄기와 바닥 빛 웅덩이 | 지도 `S` → `Level::parse` 광원 → `Renderer::stage_props`의 `shaft` | 구현 |

지역 환경 선택은 매 프레임 현재 `StageRun.def.env`에서 읽고, 개발 놀이터는 `SURFACE`를 사용한다. 지형 굽기에는 `env.trees`가 전달되고, 달빛은 정점 조명 계산 전에 `set_moonlight`로 설정된다. 현재 두 스테이지의 지도 문자열이 서로 다르므로 지형 캐시 키가 환경을 잘못 재사용하는 문제도 현재 구성에서는 보이지 않는다.

지하에서 `trees = false`여도 벽 뿌리는 `flora`가 켜져 있으면 별도 경로로 생성된다. 따라서 “나무·덤불은 없고 벽 뿌리는 남는다”는 0119 의도와 맞는다.

## 2. 수정 필요 — 떨어지는 흙의 높이가 월드 절대값

**심각도: 중간 / T2 시각 수용 전에 수정 권장**

관련 구현:
- `src/backdrop.rs`: `FALLING`의 높이 범위가 `(0.1, 6.0)`
- `drift_at`: 입자 높이를 `d.y.0 + y0.rem_euclid(hspan)`로 계산하며, 플레이어 위치 `c`는 X/Z 중심에만 사용
- `src/render.rs`: `motes` 호출에 지형 높이 정보가 전달되지 않음
- `src/render.rs`: 빛줄기 상단은 각 `S` 표지 위치에서 Y 방향으로 9m 올라감

현재 마을 지도는 `HEIGHTS`로 구역마다 바닥 높이가 달라진다. 하지만 떨어지는 흙은 바닥 높이를 조회하지 않고 월드 Y=0.1~6.0m 범위에서 순환한다. 따라서 바닥이 높은 구역에서는 입자 상당수가 바닥 아래에 놓여 지형에 가려지고, 낮은 구역에서는 바닥부터 입자 시작점까지의 높이가 달라진다. 즉, “천장에서 떨어지는 흙”의 높이와 분포가 구역 지형을 따라가지 않는다.

**권장 수정**
1. 입자 X/Z 위치에서 현재 지면 높이를 구할 수 있도록 `motes`에 지형 높이 조회 정보를 전달한다.
2. 각 입자의 수직 범위를 절대 Y가 아니라 `local_ground_y + 0.1 .. local_ground_y + ceiling_offset`로 계산한다.
3. 입자가 지면에 닿으면 해당 위치의 천장 높이에서 다시 시작하도록 순환시킨다. 최소한 지면 아래에서 생성되거나 지형을 통과해 보이는 입자는 제외한다.
4. 빛줄기와 떨어지는 흙이 같은 지역 천장 높이 가정을 사용하도록 높이 기준을 한 곳에서 관리한다. 지금처럼 빛줄기 길이(9m)와 흙 입자 절대 높이(최대 6m)가 별도로 고정되면 추후 지형 높이 변경 때 다시 어긋날 수 있다.

이 수정은 지역별 지면 높이를 무시하는 현재의 입자 배치 문제를 바로잡는 것이며, 새로운 환경 시스템을 추가하자는 제안은 아니다.

## 3. 테스트 보강 권장

현재 `regions_below_ground_have_no_moon_and_light_through_ceiling_cracks`는 지하에서 달이 없고, 달빛이 1보다 작고, 흙 입자와 `S` 표지가 하나 이상 존재하는지는 확인한다. 하지만 정본 값과 일부 환경 플래그를 충분히 고정하지 못한다.

- `e.fireflies || e.trees`를 한 번에 검사하므로, 지상에서 반딧불과 나무 중 하나가 실수로 꺼져도 통과할 수 있다. 두 값을 각각 검사해야 한다.
- 지하 `moonlight`는 `< 1.0`만 확인한다. 정본 값 `0.4`를 확인해야 한다.
- 지상에서 `falling == false`, `fireflies == true`, `trees == true`인지 각각 검사하지 않는다.
- 지하에서 `fireflies == false`, `trees == false`, `falling == true`를 각각 검사해야 한다.
- `ridge_h`(지상 1.0, 지하 2.2), 지하 안개 색, `S` 표지 수(0121 지도 기준 다섯 곳)는 현재 테스트에서 직접 검증하지 않는다.

**권장 테스트**
- 환경 표의 모든 의미 있는 플래그와 수치가 정본과 일치하는지 단위 테스트 추가.
- 마을 지도에서 `SHAFT_GLYPH` 개수가 지도 결정(0121)과 일치하는지 테스트.
- 입자 높이 수정 후, 서로 다른 바닥 높이에서 입자 범위가 각각 해당 지면 위에 유지되는지 순수 함수 테스트.

## 4. 수동 검증이 필요한 항목

헤드리스 확인 기록은 있으나, 이 분석만으로 실제 기기에서의 시각적 품질이나 성능을 통과 처리하지 않는다.

- [ ] 성소에서 하늘·달·반딧불·나무가 기존 모습으로 유지된다.
- [ ] 마을에서 달이 보이지 않고 흙빛 동굴 벽과 뿌리 천장이 읽힌다.
- [ ] 마을의 서로 다른 높이 구역에서 떨어지는 흙이 바닥 아래에 나타나지 않고 천장에서 떨어지는 것으로 읽힌다.
- [ ] 빛줄기 다섯 곳이 바닥 빛 웅덩이와 함께 보이며, 지형·카메라 각도에 따라 과도하게 잘리거나 벽을 통과하지 않는다.
- [ ] Android에서 환경 효과를 켠 상태로 목표 프레임 성능을 유지한다(0116 P5).

## 5. 결론

- **기능 누락:** 현재 코드에서 0119의 핵심 구성 요소가 빠진 것은 확인하지 못했다.
- **수정 필요:** 떨어지는 흙 입자의 높이 기준을 지형 상대값으로 바꿔야 한다.
- **테스트 보강:** 환경 플래그·수치·빛줄기 배치에 대한 회귀 테스트를 더 촘촘히 해야 한다.
- **미검증:** 실제 기기 시각 품질과 Android 성능은 별도 플레이 검증 전까지 미확인이다.

이 문서는 분석 결과만 기록한다. 구현 수정은 별도 합의 후 진행한다.
