# ChatGPT 브레인스토밍 요약(2026-11-03) — 3D ARPG, 쿼터뷰 ↔ 락온 숄더뷰

출처: https://chatgpt.com/share/6ae841fc-d964-83ec-a11a-1fa1dd414efa (사장 ↔ ChatGPT GPT-6, 사용자 메시지 9개). 원문을 옮기지 않고 결정과 근거만 적는다.

## 정해진 것(사장의 말)
1. 두 번째 게임은 **3D ARPG 쿼터뷰**, **3인칭으로 자연스럽게 전환**.
2. **잡몹은 떼로 나오는 쿼터뷰, 보스 구간은 락온 상태의 소울라이크.** 엔진(개발 스택)은 **그대로**(Rust + macroquad).
3. 보스 전환은 **플레이어가 직접 락온 버튼으로**. 카메라는 **두 모드 모두 Perspective**.
4. 3D 모델은 **마인크래프트보다만 정교하면 됨, 레트로풍**.
5. **새 프로젝트**를 만들어 **PoC + Lab**(수치가 꼭 필요한 기능은 별도 화면에서 바꿔 보며 손맛·사용감 찾기)으로 시작. 기존 KB를 활용·갱신.
6. 시나리오를 대충 잡고 테마가 나오면 그 테마풍으로 PoC — 가능.
7. 세계관은 **A 《뿌리 아래의 종말》**(다크 판타지 미스터리, 과거를 잃은 방랑자, 뿌리는 파괴와 생명을 동시에 일으키는 모호한 존재)로 뼈대만.

## ChatGPT가 제안한 것(채택 여부는 결정 기록에)
- 게임 규칙은 하나, 카메라·타깃팅·입력 기준만 모드별로(채택, `0003`).
- 엔진: Godot/Unity 권유 → 사장이 스택 유지로 결정. macroquad는 Camera3D·Perspective/Ortho가 있으나 모델·애니메이션·카메라 충돌은 직접(사실 확인: KB `reference/macroquad/3d-rendering.md`).
- 아키텍처: ECS 없이 모듈(core/world/gameplay/camera/rendering/lab), Gameplay은 카메라를 모르고 Presentation은 체력을 바꾸지 않는다(채택 — 첫 게임 규칙과 같다).
- 마일스톤 M1 3D 기반 → M2 카메라 전환·락온 → M3 공통 전투 → M4 웨이브·보스. M1+M2를 먼저(이 레포의 PoC가 M1+M2+M3 일부).
- 카메라 초기값: 전환 0.25~0.40s, 쿼터뷰 FOV 45°, 보스전 60°, 거리 4~5, 높이 2, ease in-out. 카메라 전환 시간과 전투 입력 반응은 분리.
- 가림: 충돌 당기기 → 페이드 순. 첫 프로토타입은 당기기만(채택).
- PS1풍 로우폴리 + 현대적 가독성. 잡몹은 색·실루엣으로 구분, 보스는 큰 실루엣·예고 모션.
- Lab 목록: Camera·Movement·Combat·Dodge·Lock-on·Enemy·Performance(채택, `docs/lab.md`). 프리셋 저장·비교. KB에는 일반 원리, 레포에는 실험 결과.
- 세계관 A 상세: 침식(The Blight)·종소리·핵 셋을 상징으로, 방랑자, 적 셋(뿌리의 잔재·가시짐승·뿌리의 씨앗), 첫 보스 잠들지 않는 문지기(내려치기·돌진·뿌리 파동), 첫 구역 다섯 장면, 의도적으로 미정인 질문 여섯. 대안 B 폐허 SF, C 민속 판타지.

## 친구의 조언(사장이 받아 옴, 출처 불명, Unity Cinemachine 기준)
전환 0.15~0.25s + ease, 대상을 중앙에 두지 않기(캐릭터 1/3·적 반대 1/3), 각도 차 클 때 위치 먼저·회전/FOV 살짝 늦게, 쿼터뷰 FOV 35~45°로 타협, 숄더뷰 동안 지형 페이드, 락온 순간 입력 기준 즉시 전환. → ChatGPT는 0.25~0.40s로 조정, 페이드는 뒤로. **PoC에서 확인한 것**: 카메라만 어깨로 옮기면 1/3 구도가 안 나오고 **주시점을 옆으로 밀어야** 한다(`tuning.rs` `CAM_L_FRAME`).
