# 장면 · 큰 창 · UI · 글

`CLAUDE.md`에서 옮긴 규칙이다(0278) — 문장은 그대로이고 같은 힘을 가진다. 고치는 곳: `src/app/` · `src/ui.rs` · `src/hud.rs` · `src/i18n/`.
이 영역의 파일을 고치기 전에 읽고, 구조를 바꿨으면 여기를 고친다. 굵은 머리말에서 문단만 갈랐다.

## 장면과 큰 창

장면은 `app/`(타이틀·싸움·큰 창(멈춤·화로)·끝·결과·조작·DEV — 0052).

**기초 설계는 0066**: 장면은 스택(`app/stack.rs` — 창은 `Go::Open`으로 얹고 뒤로 = `Go::Back`, 닫으면 연 줄로 돌아온다, 돌아갈 곳 깃발을 두지 않는다), 무엇 위에 그리나는 `Scene::layer()`(`_` 없는 match), 메뉴 입력(터치 = 탭)을 받나는 `Scene::is_menu()` = 싸움 층이 아닌 모든 장면 — `layer()`에서 끌어온다, 목록을 따로 두지 않는다(0152: 도감이 목록에서 빠져 터치가 안 먹었다), 처음 포커스는 `flow::focus`. 흐름은 `app/flow.rs` 순수 함수(시험), `app/mod.rs`는 그대로 한다. 화면 상태(커서·창)는 스택 칸에 — `App`에 화면별 필드를 늘리지 않는다(지금 칸의 커서 · 창은 `App::menu`, 탭을 넘겨도 이어 가는 탭 상태는 `App::tab` 한 묶음, 판에 붙은 것은 `App::this_run` — 0278 R24). 그리기는 읽기만: 무엇을 보이나는 순수한 뷰가 정한다(`equip::EquipView` · `bag::BagView` · `skills::skill_rows`/`RowFades` · `hud::near_button`, 0278 R22 — 그리기 전에 정할 것은 `App::ready_skill_rows`처럼 `draw` 들머리에서).

**목록 화면 = 줄 표 하나**(`app/menu.rs` `Menu`: 입력·그림이 같이 쓴다, 창 틀·✕·창 밖 탭·▲▼는 몰이꾼이) + 고름 함수(`Out`) — `App::menu_of`·`act`에 한 줄씩, 화면 몸은 `app/<화면>.rs`. 누를 자리는 그림이 채우고 입력이 읽는 `App::menu.hits`(`Hit`, 먼저 넣은 칸이 이긴다). 새 목록 화면 = `Scene` 한 줄 + `layer` 한 줄 + `menu_of`·`act` 한 줄씩 + 줄 표 함수 + 고름 함수. 표가 안 맞는 화면(타이틀·조작 표·묻는 창·큰 창의 상태·장비·기술·도감 탭)만 제 그림.

**큰 창 = 창 하나 + 탭(0164)**: 멈춤(Esc·Start)과 화로(쉬기)가 같은 창을 연다 — 줄 목록을 거치지 않는다. 연 곳 `flow::Host`(타이틀·멈춤·화로)가 탭 줄(`flow::tabs` — 0261 → 0263: 멈춤 = 장비·가방·기술·기록(여정 먼저 + 도감, 0265)·설정, 화로 = 성장(상태)·장비·가방·기술·가게·설정(화로의 Select = 장비 탭 `flow::hearth_select` — 다른 창을 여는 링크는 두지 않는다, 사장 "링크로 들어가는게 더 헷갈려"), 타이틀 = 설정 하나 — 설정 탭의 줄은 멈춤·화로가 같다)과 켜지는 일(`Host::edits` — 올리기·사기·되돌리기는 화로에서만)을 가르고, 탭의 장면(`Scene::Status`·`Equip`·`Skills`·`Codex`·`Shop`·`Settings`)이 그 값을 들고 다닌다. 탭 넘기기 = 스킬 버튼 둘·탭 머리 누르기 → `Go::Swap`(맨 위 칸을 바꾼다 — 쌓지 않으니 뒤로 한 번에 닫힌다, `App::tab_input`이 탭의 틱보다 먼저). "계속"·"떠나기" 줄은 없다(닫기), 처음부터·타이틀로·개발은 멈춤의 설정 탭 끝 줄(`flow::settings_rows`). 멈춤은 그 판에서 마지막에 보던 탭에서 열린다(`App::this_run.pause_tab` — 판에 붙은 한 칸(`RunState`), `flow::pause_opens`·`remembered`), Select = 장비 탭.

**몸의 문법은 어느 탭이나 같다**(`app/tabs.rs`): 왼쪽 = 고르는 것(칸·줄 — `LEFT_W`, 줄 표면 `draw_left_list`) · 오른쪽 = 고른 것의 상세(`draw_pane_head` 그림·이름·갈래·상태 한 줄 + `draw_pane`의 줄 `Ln` — 넘치면 읽는 사람이 굴린다) · 아래 = 같은 자리의 안내(`tab_foot`). 창 안에 또 창(테·제목 줄)을 그리지 않는다 — 얹는 것은 칸 곁의 작은 목록뿐(`EquipPick`·`SkillAct`). 창의 자리·크기·탭 머리·지갑(기술 점수 · 잔불)은 탭을 넘겨도 움직이지 않는다(`draw_tab_window`).

**탭 줄이 넘치면 끌어서 굴린다(0232 → 0233)**: 여백을 6까지 줄여도 넘치면 글을 줄이지 않고 가로 띠로 — 탭 줄 위의 손가락 끌기(`Actions::drag_x`)·휠이 굴리고(`App::tab_input`이 먼저 받아 몸의 목록에 넘기지 않는다), 탭을 넘기면 그 탭이 보이게 가장 적게(`ui::Strip` — 앱에 하나 `App::tab.tab_strip`, 그림 `ui.window`는 띠를 `ui::clip`으로 자르고 걸친 글은 `plain_text`), 양끝 ◀▶는 표시만(가려진 쪽에 민트 점이면 민트), 헤드리스 `tools/test/tabs.js`(터치 끌기 포함 — 탭을 더하면 그 `TABS`도). 탭 머리의 민트 점 = 지금 올릴·살 것이 있다(`tabs::tab_marked` — 화로에서만), 알림은 오른쪽 칸의 상태 줄 자리에(창이 화면을 다 쓴다). 새 탭 = `flow::Tab` 한 줄 + `tabs`·`tab_scene`·`tab_of` + `Scene` 한 줄 + 몸 파일(틱·그림) + 시험.

**장비 탭(0067 D → 0164)**: `app/equip.rs` — 인형(`Renderer::draw_doll`, 작은 타깃 + 고정 카메라 — 상태 탭과 함께 끌어 돌린다: 인형 위의 가로 끌기·마우스 끌기·패드 오른쪽 스틱 가로, 돌림판처럼 앞면이 손을 따라, 한 번 돌리면 흔들기를 멈추고 그 각에 `App::turn_doll`·`tab.doll_yaw`, 0235. 메뉴의 마우스 끌기는 6px 넘으면 터치 끌기와 같은 `drag_x`, 끈 뒤 뗀 것은 탭이 아니다) + 칸 넷 → 칸 먼저 고르고 그 칸 곁의 후보 목록(`Scene::EquipPick`), 오른쪽은 고른 것(후보면 지금 것과 견줘 `값 → 값 ▲▼`)·상태 줄 `stats::lines`. 후보는 가진 것만(못 얻은 것의 실루엣은 도감 몫, 0068).

**맨손으로 깨어난다(0220)**: 검도 얻는 무기 — 첫 지역의 깨어난 자리 곁에 떨어져 있다(`StageRun::lay_start_sword`, 상자 번호 자리 `START_SWORD`), 주우면 들고 기록·도감에 든다. 깃발 `migrated.sword`가 없는 옛 기록은 검을 지닌다.

**상태 탭(0164 → 0173)**: `app/status.rs` — 인형·체력과 기력 막대 + 고르는 줄(레벨 셋: 단의 점 다섯·다음 단의 값 / 기술 묶음: 끼운 스킬 두 칸·큰 기술·패시브 — 장신구는 장비 탭 몫) + 오른쪽 "지금 → 다음"·스킬의 설명·연 패시브와 지금의 수치. 화로에서 확인 = 올리기(묻는 창), 멈춤은 읽기만(`status::level_state`), 기술 줄에서 확인 = 기술 탭의 그 칸(탭 사이의 이음 — `status::confirm`·`skills_cursor`).

**멈춤에서 못 하는 일은 까닭을 말한다(0173)**: 아래 줄 오른쪽 끝의 "보기만" 표지(`tabs::draw_view_note`), 작은 목록 끝의 흐린 줄(`skills::Do::Away`), 확인했을 때 상태 줄 자리의 알림 — 소리만 내고 넘어가지 않는다.

**도감 그림은 손으로 본다(0252)**: 끌면 돈다(`tabs::turn_by_hand` — 인형과 같은 길, `app::codex::CodexView`), 생물은 칸 폭 전체에 카메라를 칸에 맞춰 당긴다(`draw_creature`).

**아이템 그림(0068)**: `item_view.rs` 표(아이템 → 모델·부위·각도) + `Renderer::draw_icon`(칸 크기마다 한 번 찍어 캐시)·`draw_item`(고른 것 하나만 매 프레임).

**메뉴의 그림(인형·아이템·도감 생물)은 화면 해상도(0250)**: 연구소 `render.menu fine`(기본 켬)이면 타깃 = 칸의 물리 px × 2 + 선형으로 줄여 붙임(`fit_doll_rt`·`menu_texels`), 외곽선은 게임 도트·옛 고정 크기로 센 줄 수(`Look.rows`)라 굵기의 몫이 같다 — 칸(논리 px)과 화면 배율(물리 px)을 섞어 셈하지 않는다(폰에서 도트가 세 배였다), 헤드리스 `tools/test/menu_res.js`. 새 아이템 = 표 한 줄 + 모델 부위(장신구는 `tools/art/blender/charms.py`의 부위, 이름 = 기록 키). 설명 칸은 세 줄 안이 원칙, 넘치면 **읽는 사람이 굴린다**(저절로 흐르지 않는다 — 패드 오른쪽 스틱, 휠·끌기는 칸 위에서 `Actions::point`·`Hit::Pane`, 값은 `App::tab.scroll`).

## UI 기본틀은 KB와 nail에서

**UI 기본틀은 KB와 nail에서(0065, 사장)**: 새 화면·메뉴·알림 전에 KB UI 노트(`controller-layout-and-remapping`·`hud-readability-and-quick-slots`·`roguelite-save-slots-and-continue`·`game-audio-without-a-composer` 메뉴 소리)와 nail의 같은 화면을 읽고 같은 꼴로. 둘 다에 없는 꼴이면 스터디 → 제안 → 사장 확인 뒤. 되돌릴 수 없는 일은 `Scene::Ask`(하는 일 이름 / 취소, 커서는 취소에서).

## UI

UI(0042, nail 방식): 안내는 짧게(메뉴 안내만, 전체 조작은 조작 설정 화면), 키 이름은 키캡 `ui::key`(**싸움 화면에서도** — 힌트·곁의 할 일·스킬 칸 밑, 0168: 글과 같은 빛의 낱글자는 버튼으로 안 읽힌다. 키캡 옆의 글에 제 빛을 주려면 `hud::key_line`처럼 둘로 나눠 그린다), 고정 칸은 `ui.fit`, 긴 글은 `ui::wrap`·`text_center_wrapped`, UI 크기는 `Frame::ui`(480×270 기준, 0041). 새 화면은 개발 빌드 **F4**(넘침 검사 `ui::check`)를 켜고 한국어·영어로 — 콘솔 `[ui-check]`가 없어야 한다.

**글은 칸에 맞춰 놓는다(0275)**: 줄 바꿈(`ui::wrap`)·세로 굴리기(`ListView`·`draw_pane`)·가로 굴리기(`ui::Strip`) — 남는 한 줄짜리 고정 칸(`Ui::fit`이 자르는 곳)은 `cargo test`의 `app::text_fit`이 글꼴로 잰다(GL 없이, 두 언어의 모든 글): 큰 창에 고정 칸·글을 더하면 그 시험에 한 줄, 넘치면 칸을 고친다(시험을 느슨하게 하지 않는다).

**넘치는 목록은 굴린다(0059)**: 메뉴는 `ui.menu(…, &mut ListView, cx, top, bottom)` — 위·아래 끝만 주면 넘칠 때 보이는 줄 + ▲▼, 키 커서는 창이 따라가고(가장자리 한 줄 여유) 끌기 `Actions::drag`·휠 `Actions::wheel`·▲▼ 탭은 창을 옮긴다. 화면마다 줄 간격을 줄여 맞추지 않는다.

## 글과 글꼴

글: 플레이어가 보는 글은 `i18n/<언어>.rs`(한국어·영어) 키-필드 표에만(`Strings`, 데이터 표는 `Tr`, 숫자는 `{0}` + `fill`). 글꼴은 고운바탕(보통·굵게, 0021)

**서브셋 — 표에 있는 글자만 들어 있다**: 새 글자를 쓰면 `python3 tools/fonts/subset_ui.py <원본 Regular> <원본 Bold>`(원본은 Google Fonts, 레포에 넣지 않음), 시험이 모든 글자를 본다, 표 밖 기호는 `i18n::UI_GLYPHS`. 가변 글꼴은 쓰지 않는다(fontdue가 축을 못 고름). 글꼴 하나는 아틀라스 여러 장(`ui::Face` + `glyph_shards` — 한 장 `CAP`자, 1024² 안: 2048² 아틀라스에서 Android Chrome 글자가 검은 네모였다, 0254) — 글자를 그리고 재는 것은 `Face::draw`·`width`만 지난다(macroquad `draw_text_ex`에 UI 글꼴을 바로 넘기지 않는다). 화면 글·메뉴는 `ui.rs`(UI 배율 `Frame::ui`, 커서 없이, 터치는 뗄 때), 싸움 HUD는 `hud.rs`(`hud::draw`는 구역마다 `draw_<구역>` 한 줄 — 새 구역 = 함수 하나 + 그 줄, 그리기는 월드의 규칙을 다시 세지 않는다: 쇠뇌 덧장전의 몫 `World::topup_share`, 0278 R25c). 개발 줄 F3만 영어 기본 글꼴. 연구소(랩)·DEV 창은 언어를 따른다 — 글은 `i18n/dev.rs`(랩 값 이름 표 `SPEC_KO`·쌍 `Pair` + `t`, 0080), 랩 값을 더하면 그 표에도 한 줄(시험).

## 용어

**용어(0273)**: 화면의 글(`i18n/ko.rs`·`en.rs`의 값)은 통용어로 쓴다 — 표는 `docs/decisions/0273-conventional-terms.md`. 코드·옛 문서의 말 ↔ 화면의 말: 기술 = 스킬 · 기술 점수 = 스킬 포인트 · 큰 기술 = 궁극기 · 판 = 스킬 트리 · 칸 = 노드(트리) / 슬롯(장비·스킬) · 갈래 = 계열 · 맺음 = 핵심 패시브(스킬 5단의 맺음 = 최종 효과) · 다리 = 연결 노드 · 결 = 속성 패시브 · 타입 = 속성(화상·속박·출혈·빙결·기절) · 대기 = 쿨타임 · 단 = 레벨(Lv.) · 끼우기 = 장착 · 강타 = 강공격 · 모아 치기 = 차지 공격 · 벼리기 = 강화 · 잔불로 바꾸기 = 분해 · 강한 개체 = 정예. 몸의 말도 걷는다(사장 2026-11-26): 쥐다(버튼) = 길게 누르기 · 들다/든 무기 = 장착/장착한 무기 · 메다 = 보조무기로 장착 · 빈 손 = 보조무기 미장착 시(결의 이름은 그대로) · 바꿔 들기 = 무기 교체. 세계의 이름(잔불·등잔·화로·문지기·덧옷·숫돌·종소리 조각·핵·여정·속성 이름 여덟)은 그대로. 새 글·새 문서는 그 표의 말로, 한 뜻에 한 말 — 키 이름·기록 키·코드 식별자(`Plate`·`Vein`·`Key`·`rank`)는 바꾸지 않는다(이 파일의 다른 문단은 코드의 말로 적혀 있다).

**줄표 없음 · 홀드(0273, 사장 2026-11-26)**: 화면의 글에는 줄표(—)를 쓰지 않는다(시험 `screen_text_has_no_em_dash` — 개발 창의 글은 밖) — 이름과 풀이 사이는 콜론("긴 자루: 근접 무기 가운데 가장 멀리 닿고 …" · "종소리 조각: 스킬 포인트 +1"), 문장 사이는 마침표, 덧붙는 조건 · 괄호 안은 쉼표. 조작 설명의 짧은 표기는 "꾹"이 아니라 "홀드"("홀드: 달리기").

## 앱이 내려가면
