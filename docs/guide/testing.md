# 시험 — 헤드리스 스크립트 · 개발 시나리오

`CLAUDE.md`에서 옮긴 규칙이다(0278) — 문장은 그대로이고 같은 힘을 가진다. 고치는 곳: `tools/test/` · `src/scenario.rs` · `src/app/dev.rs`.

## 헤드리스 스크립트(메뉴 길 · 장면 기다리기 · 깃발)

타이틀 줄·큰 창의 탭 줄·설정 탭의 줄(0164 — 멈춤·화로는 줄 목록이 아니라 탭이다: 스크립트는 Q·E로 넘기되 몇 번인지 세지 않고 `sceneKit.openTab(장면 이름)`으로, 멈춤은 그 판에서 마지막에 보던 탭에서 열린다)을 바꾸면 `tools/test/shot.js`·`save.js`·`leak.js`·`hearth.js`·`touch.js`·`fx.js`의 메뉴 길도 — 그리고 push 전에 CI(`deploy-web.yml`)가 도는 넷(`shot`·`touch`·`pwa`·`save`)을 **다** 돌린다(CI는 0271부터 넷을 잡마다 나란히 돌린다 — 로컬에서는 차례로: 소프트웨어 GL이 코어를 다 써서 겹치면 서로 느려진다. main의 연기 시험은 운영 빌드 `boot.js` + `pwa.js`)(0151: 멈춤에 줄 하나를 더하고 `save.js`를 안 돌려 개발판 배포가 깨졌다) — 스크립트의 키 누름은 시간이 아니라 **게임 프레임 둘**을 기다린다(`press`의 `requestAnimationFrame` 둘: macroquad는 한 프레임에 같은 키 두 번을 한 번으로 센다 — 느린 CI에서 `save.js`가 가끔 엉뚱한 슬롯을 덮었다, 2026-11-18, KB `reference/macroquad/wasm-build.md`) — **장면이 바뀌는 누름 뒤에는 시간이 아니라 장면을 기다린다**(2026-11-19: CI는 10 fps 안팎이라 "300ms"가 몇 프레임인지 모른다 — `save.js`의 덮어쓰기가 네 번 빠졌다): 게임이 맨 위 장면이 바뀐 프레임에 `window.knellScene`에 이름(`Scene`의 Debug — `Ask(Overwrite(0))`·`Slots { load: false }`·`Play` …)을 적는다(`screen::report_scene`, `App::frame`), 스크립트는 공용 `tools/test/scene.js`의 `until(앞머리|정규식, 무엇)`·`flip`(탭 넘기기)·`openTab`·`press`로 기다리고 못 오면 지금 장면을 말하며 멈춘다(서버·브라우저·콘솔 에러도 거기 한 곳 `serve`·`launch`·`watch`, 개발 창의 길은 이름으로 `dev`·`boot`·`devRow` — 0278 R13)(헤드리스 스크립트는 모두 이 꼴 — 새 길을 짤 때 `SCENES=1`이 누름·장면 차례를 찍는다, 느린 CPU 흉내는 `THROTTLE=10`). 긴 스크립트는 `sceneKit.unhurt(page)`(개발판 `window.knellTestFlags` 1 → `World::unhurt`: 방랑자가 맞지 않는다)로 도중에 쓰러지지 않게 — 시간으로 기다리던 `touch.js`가 가시짐승에 쓰러진 결과 화면을 멈춤·장비 탭이라 찍고 있었다(2026-11-19), 맞는 모습을 찍는 스크립트는 쓰지 않는다 — **흐름만 보는 스크립트는 `sceneKit.cheap(page)`**(개발판 깃발 8 — 월드 줄 수 270·2배 그리기 끔: 헤드리스의 소프트웨어 GL은 화소 수가 곧 시간이라 3배 빠르다, 화면 크기·UI 배치는 그대로. 그림을 보는 `shot.js`·`fx.js`·`menu_res.js`는 걸지 않는다, 찍힌 그림을 제 화질로 보려면 `FULL=1`)(0052 — 둘은 처음에 "키보드만 배치로"를 고르고 J·K·L로 싸운다, 마우스 배치는 `tools/test/mouse.js`, 0058).

## 개발 시나리오와 개발 창

개발 시나리오는 `scenario.rs` 표 한 줄(`checks`에 그것이 보는 PoC 번호) + `app/dev.rs` `DEV_LIST`의 (묶음, 시작할 것) 한 줄(묶음 여섯 — 하는 일로: 도구 · 모션(무기별 동작 보기 `app/motions.rs`, 판정 구간 막대) · 기술 · 스테이지 · 전투 · 성능, 0194 — 헤드리스 스크립트는 줄을 세지 않고 이름으로 연다: 개발 명령 `window.knellDev`(`sceneKit.dev`·`boot` — 이름은 `DevStart`의 Debug · `Dev(<줄>)` · `Arm(<무기>)` · `ArmSub(<무기>)`, `app::dev::DevCmd`, 시험 `every_dev_command_name_round_trips`), 창을 메뉴로 지나는 길은 `shot.js`의 `devRow(줄 이름)`(개발 창·모션 보기는 고른 줄을 장면 이름 끝에 `@Gate`·`@attack`로 붙인다), PC는 `KNELL_BOOT`(쉼표로 여럿), 0278 R13)(시험이 본다, 0075 → 0083 — 창은 nail 0269 구조: 위 묶음 탭 · 왼쪽 줄 · 오른쪽 설명 · 아래 안내, 무기·돌아가기 줄 없음 — 창 안의 작은 탭(개발 창·모션 보기·도감의 묶음)은 넘치면 가로로 굴린다 — `ui::strip_tabs`·`button_strip` + `App::tab.small_strip`, 0257. 모션 보기는 재생 시각을 장면에 들고 다녀 메뉴 소리 한 곳이 그것을 장면 바뀜으로 세지 않는다) — 타이틀·멈춤(개발판 — 설정 탭의 끝 묶음, 0164)의 개발로 들어간다. DEV에서 시작한 스테이지 판은 기록 슬롯에 쓰지 않는다(`App::dev.run`). feature `dev`(기본 켬)로 가린다. 운영판 = `--no-default-features`.
